# Windows lifecycle invariants (AR-1)

These rules govern the Windows implementation; the public SPI is unchanged.

1. The provider gate linearizes `Prepare`, `Launch` admission, launch release, and disposal admission. Native job creation and preparation registration happen under that gate. An admitted launch moves its job from the prepared map into a provider-visible launch admission; its local scope owns every subsequently created suspended process/thread until it transfers them to one execution state. The admission remains visible until transfer or cleanup finishes.
2. `DisposeAsync` wins when it sets the disposed bit under the gate. It closes unused preparations, requests stop of registered executions, and joins every admitted launch. A launch may resume a suspended target only while holding the gate and after checking the disposed bit. It registers the execution state under that same gate before returning. A losing launch kills its suspended target and closes all owned handles.
3. A running execution state is the only owner of the job, root process handle, root exit code, termination intent, and terminal task. Its observer begins with an asynchronous yield. It observes both root exit and zero active job members; any native observation failure is a failed completion, never a natural exit.
4. `WaitForCompletionAsync` only observes the execution-owned terminal task. Canceling one caller's wait neither cancels the observer nor changes the execution. Concurrent and later waiters receive the same terminal result while the provider is alive; after provider disposal the SPI requires new calls to throw. Completed results use weak retention of the issued handle plus periodic pruning, so an abandoned handle does not create unbounded provider tombstones. Equivalent record values can retrieve a completed result while the issued handle remains reachable.
5. Termination and observation serialize on the execution-state gate. Disposal requests termination and joins terminal observation before returning. Handles remain open until the state reaches terminal; then the state closes each once. Query/termination/wait operations cannot use a handle after closure.
6. Failed assignment or resume leaves the root suspended until terminated. The launch admission keeps its job and safe process/thread handles until cleanup is confirmed. If native termination cannot be confirmed, the provider retains that admission for disposal retry and reports cleanup failure instead of treating it as successful reclamation. A failed termination/observation/cleanup is diagnostic failure, not success evidence.

AR-1 regression oracles use a fresh workspace and marker for each run, finite child work, explicit barriers for race ordering, bounded outer watchdogs, and independent cleanup. A marker from an earlier run or process-ID disappearance alone is not accepted as proof.
