# B6-S3 B2 owner installation echo

**Proposed wire amendment · 2026-11-03 · GAGAMBA-RC2B-06-B6-S3-B2-WIRE-DELTA-01**

The original controller must receive owner message 36 directly from the live B2 owner. Use a fresh, single-use Linux Unix-domain sequenced-packet connection dedicated to installation evidence. Keep the recovery-owned lifeline open and serviced throughout. Release of the B2 `Ready` barrier requires two independently checked echoes and the original live association. Owner acceptance of this proposal is outstanding.

This amends WI-03 for the non-integrated, non-delegated v2 B2 lifeline path. It also supplies its v2 bootstrap field placement. For integrated v2 the accepted recovery 9/10, rendezvous 8 and GID1 ordering remain governing. The delegated-parent non-integrated fixture allocates a domain without message 24. Reject a qualified request for that combination **before** opening the delegated parent or creating a journal/domain. Preserve both legacy v1 branches in their existing unqualified scope. ## 1. Authentication decision

C denotes the original controller, R its detached recovery child, O the original owner child of R. The kernel, the verified bootstrap code and the root installation are within the accepted trust boundary. R's trusted launch act identifies one process. R has no vote on whether that process supplied matching installation evidence. Treat all packets, descriptor roles and peer-supplied identities as hostile inputs. [B6 threat model, ``3–5](rc2b-06-b6-installed-artifact-trust.md)

* C generates a fresh original session internally for every qualified launch, retains its execution GUID, protocol lease GUID and independent S2 result, and creates the listener **before** R is started. C binds its nonempty execution/lease to this one attempt. Refuse reused session input. Use an abstract `sockaddr_un` with family `AF_UNIX`, then a zero byte and exactly ASCII `gagamba.b6.b2.` followed by the session GUID in 32 lowercase `N` digits. Supply the precise address length with no terminal NUL or padding. Bind once, listen backlog 1, accept once and close listener. Collision, wrong first connector or extra connection cannot trigger a retry. The public address routes packets and grants no trust.
* Use `SOCK_SEQPACKET|SOCK_CLOEXEC|SOCK_NONBLOCK` and `accept4` with both flags. Only O calls connect, after message 24 and receipt of 38. No evidence socket is accessible to executed R/O through inheritance or `SCM_RIGHTS`. C's listener is excluded from child inheritance. One accepted socket, one connecting socket, no filesystem socket to unlink. Use the real Linux credentials captured at listen/connect. A pair created by C or R and then handed down would identify its creator at both ends. Passing that pair does not rebind `SO_PEERPIDFD` to the new holder. [Linux Unix socket implementation](https://github.com/torvalds/linux/blob/v6.6/net/unix/af_unix.c) · [Linux unix(7)](https://www.man7.org/linux/man-pages/man7/unix.7.html)
* R authenticates C using the inherited, distinct control and credential sockets, real parent, non-root credentials, original C pidfd and one-shot Associate. C retains a CLOEXEC pidfd for the exact child returned by its verified R launch before delivering the bootstrap/Associate. R creates the existing private lifeline, starts exactly one verified O and seals an in-memory association of scope, returned Process object, retained spawn pidfd, lifeline, execution, lease and original session. No API accepts an owner PID, path or fd to fill or replace this slot. Before exporting it, require the same registered Process by reference and same live safe handle from this spawn, and receive 24 on this spawn's exclusive lifeline in answer to 23. R closes the parent copy of the child's endpoint at spawn. Only O inherits it and O never gives it away. A child lost before pidfd_open cannot answer this subsequent exchange. Missing liveness, inherited copies, reaping/reuse uncertainty or an ambiguous spawn fails. Apply the corresponding exclusive-inheritance and post-pin Associate/9 checks to the R launch. Preserve R as parent, subreaper and sole reaper of O.
* R's one-shot trusted launch code exports only this retained O reference to C (11), and R's previously pinned original C reference to O (38). Neither descriptor is reopened from a packet PID. C and O both compare their own live peer pidfd obtained from `SO_PEERPIDFD` against the expected retained reference. Require exact size and `SO_PEERCRED` PID, real/effective UID and GID agreement, unprivileged identities, three distinct live PIDs, same PID/user and time namespaces, trusted procfs, and the recorded parent chain O→R→C. For both live references bracket reading kernel fdinfo Pid, /proc PID status PPid and namespace links with successful not-exited polls. O also checks getppid and its inherited R socket against its pinned R. C checks R against its original child. A dead pin, unmatched peer, inconclusive procfs read or missing feature refuses. Never open a replacement by numeric PID. A pidfd is a process reference with OS-defined operations. The B2 verifier's handle interface permits only identity, poll and dispose.
* On each direct socket require `SO_PASSCRED` before application data is sent (set on C's listener after bind, on accepted socket before 37, on O's socket before connect). Send no user cmsgs. On each M1OP record require precisely one kernel-validated `SOL_SOCKET/SCM_CREDENTIALS` of size `sizeof(ucred)=12` matching the pinned opposite process, zero rights, no unknown ancillary data or truncation. Both actors must lack effective/permitted credential-forging capabilities in the governing user namespace. Check the peer pin still live around acceptance. This also rejects a different writer using a leaked socket under the supported process model. Require a native positive on the actual target kernel. [Linux credential rules](https://www.man7.org/linux/man-pages/man7/unix.7.html)
* A correct R packet, another child with identical installed bytes, a copied echo and the right claimed PID cannot supply a record from O on that connection. Conversely O receives its expectation from C only after authenticating the original C. This proof relies on the accepted trusted bootstrap accurately pinning the designated child and the kernel enforcing process and descriptor isolation within the model. If a Byzantine launcher deliberately starts and registers an impostor as its original child, matched pidfds and lineage can authenticate that impostor. This proposal makes no such Byzantine-launch guarantee. R can withhold progress or stop at any time. There is no transferable signing key or RELEASE credential here.

### Alternatives considered

| Criterion | A. Fresh direct evidence connection (selected) | B. R forwards owner evidence |
|---|---|---|
| Authentication and recovery trust | C compares actual kernel peer and record sender to its original spawn reference. O checks C independently. | The kernel identifies R as sender of forwarded bytes. A serialized PID, ucred, pidfd or hash does not authenticate the inner bytes. |
| Identity provenance | C obtains the expected projection from S2 before spawning. | Same independent expectation required. Equality alone lets R copy public digests. |
| Authority and lifeline | Existing 23–26 remain stop-capable. Evidence path has only 37/36, with no rights. | A separate relay could leave stopping intact only if it neither blocks the lifeline nor admits generic nested control. |
| Descriptor exposure | Two one-shot copies of existing lifetime references. Neither evidence endpoint is transferred. | A plain relay needs none but is forgeable. Authenticated key delivery would require a second trusted path or new trust principal. |
| Sequences and replay | Fresh direct per-direction sequence, fresh C session and socket, exact phases and pinned lifetimes. | Would need both preserved inner and new outer sequence, challenge and duplicate tracking. A fresh nonce seen by R still lets R forge. |
| Failure and complexity | One join at C, one confirmation at R, three sockets transiently including listener, two lifetime transfers, four new IDs beyond 9/10/36. Every partial state has a deadline. | At least a forwarding envelope and a signing/key-binding exchange plus dual parser/state. R dying between receipt and forwarding loses the evidence and must refuse. |
| Compatibility and falsifiability | v2 B2 only. Exercise wrong actual peer, fd, closure, packet, order and timing against known positives. | A relay can be falsified by R generating the same inner packet. There is no provisioned owner-exclusive key for a native positive. |
| Native qualification | Requires a suitable qualified installation, qualified helper launch and demonstrated AF_UNIX/pidfd/credential behavior. | Also requires independently verified end-to-end key provenance in addition to the same installed/loaded gates. |

For B, an illustrative **unallocated** RecoveryWire type 13 R→C could carry the exact original 48-byte M1OP header and 36 payload as bounded opaque bytes. R owns the outer recovery sequence, O the inner sequence. C would need to verify an owner-only authenticator over domain, both role identities, execution, lease, original session, C's fresh challenge and the exact inner bytes before consuming a single pending owner slot. It must refuse nested arbitrary IDs, duplicate forwards even with a new outer sequence, substitution, replay and incomplete delivery. Neither the Associate secret (known to R), a transmitted nonce, a self-generated verification key delivered by R, nor GID1's handshake confirmations authenticate those forwarded bytes. R can replace payload and recompute anything made solely from material it holds. Establishing an ephemeral owner-exclusive key on the authenticated direct channel would first require A, then a redundant relay. Long-term signing keys would change provisioning and trust. **B is insufficient under the accepted bootstrap.** Type 13 is forbidden in this amendment.

For a handed-down socketpair variant of A, the creator initially owns both ends, keeps one and would have to convey the other through R to O, discard every intermediate duplicate, and authenticate each actual writer independently of static peer credentials. A viable variant would let C create the pair, arm SO_PASSCRED on both ends, keep the C end and pass only the owner end via the authenticated R setup to the single O. R must close its intermediate copy immediately. C would authenticate the actual writer of 36 by SCM_CREDENTIALS against the retained spawn pin, O the author of 37 against the original C pin. The extra aliases and ancillary transfers add partial-failure cases without removing the need to pin the original child. Connecting the final peers directly avoids that transfer. Integrated GID1 already authenticates freshly connected stream peers and an original-session transcript, but B2 lacks its listener, lifetime bootstrap and verified association. Its established type-16 dispatch includes release/control traffic. Reuse the live-peer checks, with the additional procfs and per-record checks above. B2 must never construct a GID1 `DirectControl` channel or enter the integrated preparation transaction.

## 2. Trusted installation and qualified bootstrap

C runs argument-free `InstalledFileSystem.VerifyActive()` under its production fixed root. Require Qualified after the exact manifest/14 files, receipt-selected record, host/platform and final selector checks. Return the immutable typed projection from that same successful verification pass, retaining its qualification ID. Today's `InstalledResult` drops all but digest and ID. Extend the internal result without adding a caller-supplied verifier, parsing operator text, or reopening an arbitrary manifest. Launch only the root-owned installed roles with the accepted pinned runtime, cleared environment and verified assembly/loader bindings. Plain `dotnet` from PATH and caller-provided five-file hashes cannot satisfy v2. F02's `/etc` gate belongs only to privileged publication. Its runtime decision is the fixed `/opt/gagamba` receipt and selected record. [S2 acceptance](../decisions/rc2b-06-b6-impl-01-s2-owner-acceptance.md) · [F02 decision](../decisions/rc2b-06-b6-s2-f02-trust-store-owner-decision.md)

Use design section 6.1's InstallationIdentity. The installation generation is the 32 raw bytes of the S2 manifest digest. For this exchange define each five-file role hash as SHA-256 of ASCII `gagamba-b6-role-v1`, byte 00, role byte (0 R or 1 O), then five raw 32-byte SHA-256 file hashes in fixed suffix order `contract, deps, entry, m1, runtimeconfig` for that role. Exactly one S2 manifest role per suffix. No hex text, delimiters between hashes, or filesystem iteration order. Coordinator and filter are the exact corresponding S2 roles. Runtime inventory is the manifest platform inventory digest. Manifest schema, protocol constants and exact profile strings must agree with the validated S2 manifest. This projection does not alter the manifest or its artifact-set digest.

R and O each reverify the qualified installed set locally, bind its digest to their received expectation, hash all five actual role files from the protected generation and compare each role/path/hash. Verify the entry assembly and the two loaded private dependency assemblies' actual Location and pinned device/inode/hash, exact deps/runtimeconfig bytes used, host, framework and loader against the accepted closure. Resolve lazily loaded dependencies before emission. Refuse empty locations, duplicate/foreign application assemblies, uncertain loaded paths or unmapped required runtime dependencies. New production checks must demonstrate what the process actually consumed. Hashing named files or echoing a claimed set alone fails. C verifies its own loaded provider. Before 12 and final qualified return revalidate the original S2 selection (same Qualified digest, qualification ID and verified projection). A change refuses this attempt. It cannot adopt the new generation. Later pre-RELEASE checks, native loader qualification and HD-1–HD-5 stay separately gated.

Bootstrap v2 for non-integrated B2 retains the base JSON fields, `Integrated=null`, `DelegatedParent=null` and adds exactly `B2InstallationIdentity` (full section 6.2.2 InstallationIdentity object) and `B2DeadlineNs` (positive canonical signed 64-bit integer, absolute Linux CLOCK_MONOTONIC nanoseconds). Integrated v2 uses `Integrated.InstallationIdentity` only and forbids both B2 fields. On a qualified request refuse v1, missing/both locations, mismatched topology, duplicate/unknown fields, noncanonical numbers, non-lowercase 64-hex digests, empty/all-zero identities, wrong constants and stale deadline. Original `Session` is the fresh C-generated GUID. Use the credential fd, max 8192 UTF-8 JSON bytes, no rights. The B2 owner entry selector for v2 is exactly `--b2-lifeline 2` on the pinned child with the existing execution/lease and inherited bootstrap fd. A selector cannot authorize qualification. The old selector 1 and v1 validation retain their original behavior.

## 3. Frames and roles

Each packet is exactly one version-1 M1OP record. Offsets in bytes: magic u32 LE @0 `0x4D314F50`, version u16 LE @4 = 1, type u8 @6, reserved u8 @7 = 0, execution Guid @8, protocol lease-generation Guid @24, sequence u32 LE @40, payload length u32 LE @44, bytes @48. GUIDs use `Guid.TryWriteBytes` / `new Guid(span)` in existing .NET byte order. RecoveryWire changes only octet 0 by XOR 0x20. No GID1 wrapper in B2. Exact lengths, range checks before arithmetic, no trailing bytes or unknown flags. Decode only against the current channel, sender, bootstrap version, descriptor role and phase. Cross-enveloping or casting an owner type into a recovery type conveys no authority.

| ID and direction | Channel, payload, descriptors |
|---|---|
| Recovery 1, C→R | Existing Associate. 48 bytes, original session Guid then secret[32]. Zero rights. |
| Recovery 9, R→C | Original control, role-0 echo below. Zero rights. |
| Recovery 10, C→R | Original control, exactly 36 bytes. Success u8 @0, reason u8 @1, zero u16 @2, expected S2 digest[32] @4. Success=(1,0) only. Refusal=(0,1..5) with historical digest/closure/protocol/generation/qualified reasons. Unparseable requests close/stop. |
| Owner 23/24, R→O/O→R | Original lifeline, original B2StartLifeline JSON / empty B2LifelineReady. Both zero rights. |
| **Owner 38 B2EchoBootstrap**, R→O | Only v2 lifeline after 24. Exactly 40 bytes: session Guid @0, C/R/O PID i32 LE @16/20/24, zero u32 @28, B2DeadlineNs i64 LE @32. Exactly one SCM_RIGHTS fd, R's original C pidfd. |
| **Recovery 11 B2OwnerBound**, R→C | Only v2 inherited control after 24. Same 40-byte binding, exactly one SCM_RIGHTS fd, R's retained O pidfd from this spawn. No inner owner frame. |
| **Owner 37 B2OwnerExpectation**, C→O | Only authenticated direct B2 evidence socket. Session Guid @0, followed by the full identity defined below at @16. Zero rights. |
| Owner 36 OwnerInstallationEcho, O→C | Only authenticated direct B2 evidence socket in this topology. Role-1 echo below, zero rights. |
| **Recovery 12 B2OwnerEchoAccepted**, C→R | Only v2 control, after verified 36. Exactly 48 bytes: session Guid @0 and original expected artifact-set digest @16. Zero rights. R compares both. Positive only. Failure uses existing Stop/transport loss. |
| Recovery 2, R→C | Existing Ready snapshot, same JSON and 4096-byte bound, zero rights. Verify live original PIDs and clean pre-stop snapshot before returning a qualified connection. |

37 contains six raw SHA-256 fields at absolute payload offsets 16,48,80,112,144,176 (artifact set, owner closure, recovery closure, coordinator, seccomp filter, runtime inventory), then LE u16 manifest schema, owner protocol, coordinator protocol, bootstrap at 208,210,212,214. At 216 place Qualified u8=1, then id length u8 at 217, ASCII ID at 218, version length u8, ASCII version. Lengths 1..64 each, printable ASCII, exact verified profile values. Length = 219 + both string lengths (max 347). Generation is identical to artifact set by validation, with no second representation. Refuse trailing bytes. Neither 37 nor the qualified bit suffices for O's local checks.

Echoes 9 and 36 share the accepted projection: raw artifact-set digest[32] @0, computed sender-role hash[32] @32, u16 LE owner protocol/coordinator protocol/bootstrap @64/66/68, role u8 @70, Qualified u8 @71, four zero bytes @72. B2 v2 emits the canonical no-optional-tail form, **exactly 76 bytes**. Profile/version are checked in the full qualified identity and manifest before emission. B2 accepts Qualified=1 and the unique expected role only. Require every digest and protocol field to match the original independently verified projection. The schema and installation generation checks are distinct from the 16-byte lease GUID check. All new payloads have a 512-byte hard ceiling and the narrower exact shapes above. These B2 canonical forms do not redefine the accepted integrated profile.

Separate send/receive counters on each original socket use the existing sequencer, starting at 1. Successful B2 trace, with type.sequence pairs:

~~~text
C→R control   1.1 Associate   10.2 response   12.3 accepted
R→C control   9.1 echo       11.2 bound       2.3 Ready
R→O lifeline 23.1 start      38.2 bootstrap   [25.next stop]
O→R lifeline 24.1 ready                       [26.next observed]
C→O evidence 37.1 expectation
O→C evidence 36.1 echo
~~~

Counters continue normally after Ready. A Stop consumes its sender's next sequence and permanently preempts the positive path, including if it replaces 38 or 12. Only the original recipient advances its receive counter after complete validation. Invalid input is terminal, with no resynchronization. Use channel-specific transfer validation for 38 and 11. Do not globally loosen OwnerProtocol's default payload check or its descriptor allowlist. For integrated direct 36 the prior WI-05 still applies. Refuse 36/37 on recovery-only control/lifeline, 37 on GID1, 38 on evidence/GID1, 11/12 on any other recovery version/topology. No AllowAny receive. The B2 evidence socket can never accept a control, stop, capture, journal, staging, domain, writer, capability or RELEASE message, even with valid credentials.

## 4. Transition barrier, ordering and lifetimes

~~~text
C                        R (subreaper)                       O
S2 Qualified → spawn R   validate parent/control/credential
bootstrap v2 + 1 ──────► authenticate once, verify installed + loaded R
compare S2   ◄───────── 9
10 success ────────────► validate C result
                         create private pair, spawn/pin O ─► own single child end
                         23 ───────────────────────────────► pin R, arm stop observer
                         ◄───────────────────────────────── 24 B2LifelineReady
                         arm/continue R stop policy
                         38 + original C pidfd ────────────► validate once
11 + original O pidfd ◄─ publish sealed spawn reference
accept O connect ◄───────────────────────────────────────── connect to C listener
verify actual O          R monitors both peers               verify actual C
37 + S2 expectation ──────────────────────────────────────► verify O's loaded closure
verify 36 + stream end ◄────────────────────────────────── 36, shutdown(SHUT_WR)
recheck S2/lives, 12 ──► atomically gate Ready if no stop
accept Ready ◄───────── 2 and usual snapshot
return qualified only after rechecking original binding and no loss/stop
~~~

The diagram describes successful causality. The connect may queue before C consumes 11. C may not authenticate/use it or send 37 until 11 has passed. O never connects until its own 24 has been sent and it has validated 38. R sends 38 and 11 only after **receiving** 24. C's acceptance of 36 records evidence locally. Only C can send 12. R may then publish `ready.json` and existing Ready once. C may expose a qualified result only after validating Ready, its clean snapshot and final local checks. A serialized snapshot, marker or successful send of 12 cannot satisfy C's gate. No fourth acknowledgement is needed. A local R Ready followed by lost transport never creates a C-side qualified result.

For 11/38 validate the three PIDs against local roles, the session and unexpired D, the zero reserved field and the expected live references. O initially obtains session/D from the one authenticated 38 and pins them once. C compares them to its stored values. At 37 O requires that same session on the authenticated C connection. A preconnected socket or merely queued 36 cannot advance a state. At 10 require the original digest, exact success/reason pairing and a live C association before spawning O.

For v2 Ready decode exactly the existing RecoverySnapshot JSON property set once each with native types, canonical integer grammar and no trailing value or unknown fields. Require RecoveryPid, OwnerPid and ControllerPid equal the three pinned PIDs, SessionId equal R's setsid process ID (distinct from the session GUID), Subreaper true, StopCount=RetainedDomains=0, Cause and StopDeadline null, NativeStop exactly "Unproven", and every remaining boolean false, including ReleaseAuthority, OwnerAcknowledged, ControllerLost, OwnerExited and all cleanup flags. R prepares this snapshot outside its safety lock, drains pending loss/stop, then checks the latch, pins and D and sends Ready once nonblocking under that gate. Failed send latches loss. Publish the diagnostic ready.json only after successful send, outside the safety loop. C completes the final selector check outside its gate, services pending terminal control events, polls both pidfds again and commits exactly once under its local cancellation/stop lock. A remote death after the last successful observation always remains possible. Existing post-commit stopping owns that race.

**Bounds.** After initial S2 verification, C sets D before spawning R to min(now+7000 ms, any already applicable earlier operation/admission deadline), using checked monotonic ns. R/O validate 0 < D-now ≤ 7000 ms on receipt. Use the same clock domain, fail on unsupported clock/namespace. Every send, receive, bind, connect, accept, half-close/drain, verification job and readiness gate is bounded by D and all earlier relevant bounds; each echo exchange also has at most 5000 ms from its start. Keep tighter existing 5000 ms bootstrap/Associate, 3000 ms wait for 24 and legacy poll intervals. No operation, EINTR, partial handshake, duplicate or reconnect resets any clock. R's existing 30 s bootstrap lifetime starts by receipt of 24, O's 35 s lifetime by sending 24. Preserve once-only two-second RecoveryObligation and the B5 durable C3 deadline in their respective clock domains. Stop starts immediately on an observed trigger and does not wait for D.

**Concurrency and loss.** Arm the original safety duties before exposing 24 or starting blocking work. R monitors C pidfd/control throughout qualification, and O's spawn pidfd/lifeline as soon as available. O's single lifeline reader monitors R pidfd, EOF and stop independently of its identity worker. In the post-24 state that reader can receive either one rights-bearing 38 or 25; after 38 only the original stop protocol remains. R reads 24/26 and controls one sequencer per direction; serialize 38/25 sends. C has one control reader/writer owner and one bounded evidence exchange. Each actor serializes its positive transition against a terminal stop latch. Service already pending exit, error, timeout and stop before progressing; check liveness before and after the expensive work and at each barrier. Never hold the safety lock across filesystem I/O, evidence writes, hashing, socket waits or disposal joins. At most one cancellable verification job per actor. Late completion after stop is ignored. Close worker-owned handles by single-owner disposal, allow process termination without waiting for stuck reads, and refuse future attempts if a prior C-side worker cannot be reclaimed. A blocked check cannot create unbounded workers, delay 25/26 or keep the helper alive.

For one-shot framing C sends exactly 37 then half-closes its write half. O consumes exactly that record and the ensuing kernel write-half shutdown before allowing 36. O sends exactly 36 then half-closes its write half. C similarly drains through peer shutdown before sending 12. Validate records in order. A second data packet, even empty, refuses regardless of sequence or whether RDHUP is also pending. Native acceptance must distinguish an empty datagram (including its credentials/rights) from exhausted queue plus peer shutdown; require actual peer half-close indication and zero further records, with live peer pidfd. `recvmsg()==0` or poll readiness in isolation is insufficient. Poll/read nonblocking under D. After the validated half-closes both retain the direct socket until their local drain finishes; each then closes its own socket. Subsequent retries have no listener or open gate.

**Descriptor custody.** The only new rights-bearing transfers are one C pidfd R→O in 38 and one O pidfd R→C in 11. R sends a borrowed live scoped reference under the custody lock. Successful send creates a kernel-queued duplicate, R keeps each original for its existing duties. Queued-but-unconsumed references die with the receiving socket. Receive with `MSG_CMSG_CLOEXEC`; require exactly one complete `SOL_SOCKET/SCM_RIGHTS` of one int, fd > 2, CLOEXEC, real pidfd type (kernel pidfd fdinfo plus live PID), process and role checks. Reject socket/file/pipe, sibling/duplicate, unexpected/truncated cmsgs, payload truncation or wrong count; close **all** installed fds even on malformed, zero-length or truncated input. Parse and collect installed rights on every rejection path before detaching ownership. Never close a number supplied in payload. Validate CLOEXEC immediately for kernel-produced peer pidfds too. Received handles belong to the record until transferred once into a scoped owner. Single-close under serialized use. O/C release bootstrap and peer references on failure or their last barrier use; C retains the original O and R pins through final Ready/S2 validation. R retains original references under its existing bounded lifetime and reaps as today. O's original R pidfd remains its independent stop reference. No sender moves the only stop/lifetime handle.

Keep the original credential/control and lifeline ends distinct; mark every non-child end CLOEXEC before any spawn. For qualified launch export only the explicitly intended child ends (besides existing standard streams) via a spawn-local fd allowlist with atomic CLOEXEC creation and explicit child mappings. No process-wide inheritable window under concurrent spawns. Protect inherited ends before another exec, close unused ends in all processes, and close credential immediately after bootstrap. Evidence sockets are never inherited by any helper. The evidence reader admits zero rights; existing rights-only `FdPassing` needs a narrowly scoped credential-aware receive mode for evidence. Check all cmsgs and close on errors without widening the old parser. Neither a release fd nor any domain/staging/writer handle is admissible. The B2 lifeline-only branch has no physical writer. Where one exists the owner remains the sole writer and one attempt remains the limit. R can stop, observe and clean up under its retained evidence. No journal, disk identity or success bit recreates authority. HELD, protected capture and Unknown remain governed by the existing paths.
