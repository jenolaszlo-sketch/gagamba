## Frozen future artifact binding

The selected artifact identity is `gagamba-authority/validation-launch`, Linux x86-64 ELF for the initially scoped Linux x64/glibc host, installed as the fixed root-protected executable `/usr/local/libexec/gagamba-authority/validation-launch`. Gagamba owns its native project at future directory `native/gagamba-authority/` and future packaging entry `eng/linux-m1/build-validation-authority-candidate.sh`. Those locations are design reservations, outside the initial managed file allowlist. No project, packaging change or artifact is created here. Additional architectures/platforms require explicit qualification; Windows managed tests establish no Linux eligibility.

The L entry grammar is frozen as exactly six arguments, in this order: `--phase <pre|post> --catalog <catalogId> --expected-catalog-sha256 <Hk>`. Catalog ID uses the existing frozen identifier grammar; Hk is 64 lowercase hex. Reject extra/duplicate/unknown options, positional substitutes and unsupported phase. No executable, args, environment, UID, root path, approval file or closure override is accepted. A explicitly invokes this entry as host root under its separately authorized administrative context. No setuid bit, file capabilities, service, daemon or reusable escalation facility is added. This grammar binds future L only; the initial managed contract has no CLI.

Future C and D are distinct dedicated production carriers, reserved as `src/Gagamba.Validation.Controller/Gagamba.Validation.Controller.csproj` and `src/Gagamba.Validation.Driver/Gagamba.Validation.Driver.csproj`; they are not initial E-5 files. The current B2Controller fixture is not approved for either validation role and the older `installed-b2`/`installed-b3` proposal is not adopted. E-6 owns the controller integration; E-7 owns the driver implementation/closure and C-to-D adapter. Their exact emitted artifacts and full package manifests must be bound at those entry gates; until then the catalog's C/D hashes remain required expectations without verified installed realizations. Changing this carrier choice requires an explicit follow-up design decision, not fixture reuse by convenience.

## Required closure and verification contract

L's closure is the exact executable plus every executable mapping dependency: ELF interpreter if present, recursively required shared objects and helpers, any runtime-loaded libraries, and fixed configuration affecting selection/loading/privilege/bootstrap. No plugin, arbitrary loader search, inherited loader/debug/profiler configuration or test instrumentation is permitted. A statically linked build must prove its actual dependency absence; a filename or linker flag is insufficient. C/D closures additionally include the actual dotnet host/runtime, managed assemblies, native dependencies, `.deps.json`, `.runtimeconfig.json` and fixed loading configuration. Installed provider closure is not a substitute for the embedding C or D closure.

For L, define a versioned closure inventory as exact reviewed bytes plus an ordered entry table: role, absolute installed path, regular-file length and raw SHA-256, uid/gid/mode/link-count expectation, executable/loader role, and dependency edges. Its raw inventory SHA-256 is the **L closure identity**. The future native package must freeze the inventory encoding and actual values before build/installation authorization; this is a packaging prerequisite, not permission for the managed implementation to invent a serializer. Initial E-5 compares opaque 32-byte closure identities and never computes or issues a closure identity. C/D use their catalog-bound reviewed closure inventories and hash contract; no K schema change or invented L field is allowed. A's protected installation/review record supplies expected L executable and closure digests independently of K. K supplies expected C and D closures; approved package manifests supply their executable digests.

Before a live L/C handoff, require all of: exact source commit/tree and build recipe/toolchain; independent artifact selection and raw digest measurement; protected installation and safe ancestor/file metadata; actual executable/loader/runtime identity readback at the original retained process; complete mapped dependency agreement and no unreviewed instrumentation; liveness bracketed observations and original spawn/parentage; host/boot/namespace binding and permanent privilege-drop evidence. A independently verifies L before its response; L independently verifies original C; C independently verifies original parent L. Later C independently verifies D when spawning it. A record copied from a suspect process cannot supply its own expected values. Read/verification-to-use races retain the accepted observation residual; retained references and fresh barriers do not establish an atomic root-mutation lock.

Missing inventory, unavailable measurement, wrong digest, unexpected dependency, unsafe metadata, source/artifact mismatch, substituted process or unknown drop evidence refuses before live issuance/consumption or dispatch. No search, best effort, implicit trust, legacy fallback or alternate executable is permitted. Concrete native measurements, inventory bytes, producer build and independent native evidence are **absent**, not verified. The smallest future investigation is a separately commissioned unprivileged artifact/build-closure design and measurement exercise followed by separately authorized protected-host qualification; neither is required to compare supplied opaque identities in the initial model. The live gates remain blocked until they exist.
