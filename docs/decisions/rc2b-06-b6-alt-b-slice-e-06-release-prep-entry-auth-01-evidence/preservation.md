# Entry verification and preservation

This commission verifies contract inputs and repository integrity. Prospective implementation, builds, runtime activation, operational approval and protected tests are outside its scope. Historical executions retain their original evidence and dates.

- Preflight checks exact HEAD/tree/branch, E-5 ancestry, canonical worktree, clean tracked paths/index, zero stashes, and both configured origin URLs. Read-only `git ls-remote --exit-code origin refs/heads/main` verifies published main independently of the local tracking ref. No ref synchronization is required.
- The [preflight receipt](preflight.json) records 19 historical manifests with 1,054 entries plus the preceding E-6 assessment's self-excluded 19-entry manifest at the exact pinned revisions. Each manifest and member was checked against its recorded commit, the starting Git objects and starting checkout. The new assessment delta was checked against that exact boundary. The original untracked inventory was checked by path, length and raw SHA-256 for all 44 entries. The accepted implementation files were checked for byte identity and executable-scope differences.
- The [governing identities](source-identities.json) distinguish Git blob ID, exact blob SHA-256 and raw worktree SHA-256, including normal line-ending conversion of existing sources. The local F02 and Alternative B copies were verified by SHA-256. Their external ancestry and durability remain separate.
- The three current status pages are E-4 manifest members at commit `1116c66d7858e6000f0001a0abe39319e4e694be`. This commission inserts one current E-6 note per file as requested. At both staged and committed checks, removing precisely that note must reconstruct the exact original member bytes and hash. The three pinned E-4 historical blobs remain the verification boundary for those historical status snapshots. The predecessor verifier's assertion that every historical file also equals today's checkout applied before the authorized status updates. The other 1,070 historical/assessment entries must continue to match both the pinned Git blobs and raw working files. All previous status text remains verbatim.
- Before committing, check the exact staged paths and the staged Git bytes against the [new authorization manifest](SHA256SUMS.txt), and reverify prior manifests, exact allowlist absence, frozen executable artifacts and all 44 historical untracked files. Check that the three notes are the only changes to existing documents and that no branch or tag addition or linked worktree occurred. The package manifest covers the decision and every annex file other than itself. The revision-bound checkout receipt verifies the three status notes separately.
- After the single documentation commit, verify its parent, final tree, exact delta, clean tracked checkout/index, historical manifest boundaries, raw historical files, status reconstruction, evidence manifest and remote-tracking state. Record exact final HEAD/tree and final checks in an external receipt to avoid a self-referential commit hash. Keep publication at the existing GitHub revision.
