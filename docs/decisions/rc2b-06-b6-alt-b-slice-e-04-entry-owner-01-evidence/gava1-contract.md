# GAVA1 contract reconciliation

[F02 Mechanism B acceptance §2](../rc2b-06-b6-f02-mechanism-b-owner-acceptance.md) binds the 15-file final recheck manifest. Its `actor-and-descriptor-binding.md` entry (F1 below) supplies the exact GAVA1 protocol. [Alternative B owner §§3.3–3.5 and 4](../rc2b-06-b6-integrated-start-authority-owner-decision-01.md) carries that protocol forward and adds the validation-only ordering amendment. [Governing identities](governing-identities.json) records the verified Git blobs, file hashes and exact external manifest membership. The [frozen GAVA1 section](gava1-frozen-excerpt.txt) reproduces the accepted section byte for byte. Its scope includes surrounding message types so a future reader can preserve the boundary of a proposed types 4–7 implementation.

| ID | Normative source | Frozen rule |
|---|---|---|
| G01 | F1 “Common validation sideband frame GAVA1” | Dedicated validation sideband. Exact ASCII magic `GAVA` at offsets 0–3, u16 LE version 1 at 4, u8 type at 6, u8 sender role at 7 (L=1, C=2, R=3, O=4), u32 LE payload length at 8, u32 LE sequence at 12. Three 16-byte nonempty GUIDs at 16, 32 and 48 in session, execution, lease order, with .NET `TryWriteBytes` byte order. Header is exactly 64 bytes. |
| G02 | F1 exact message table | Bound is 128 payload bytes for the common sideband, further constrained by exact type-specific sizes. Header and payload must occupy exactly one record with no trailing bytes. Unknown version, type or role or mismatched length refuses. The separately specified administrative exchange is outside this bound and outside the proposed component. |
| G03 | F1 table rows 4–5 and per-direction sequence paragraph | INIT type 4, C→R or R→O, 64 bytes, capability digest then catalog digest (32 raw bytes each), zero rights. CONTEXT-ACK type 5, R→C or O→R, 32 bytes, capability digest, zero rights. INIT is first in its direction before effects beyond startup/stop service. ACK is first in the reverse direction after local grant/catalog/loaded checks. ACK carries the capability digest only. Its catalog binding comes from the verified original context, reconciling Alternative B compatibility's summary of the exchange. |
| G04 | F1 table rows 6–7 and direct context paragraph | DIRECT-CONTEXT type 6, C→O, 64 bytes, capability digest then catalog digest, zero rights. DIRECT-ACK type 7, O→C, 32 bytes, capability digest, zero rights. These are independent directions with sequence 1. Original O compares inherited context and the direct proof must use the original C/O pins. No R forwarding or additional control payload. |
| G05 | F1 direction ledger and refusal rule | Independent direction sequences begin at 1 and advance only on a fully valid record. One-shot expected type, role, direction, identity tuple and context must be supplied from the intended transaction. No wrap, replay, reconnect or resynchronization. Types 1–3 and 8 have their own L–C contract and refuse on the proposed E-4 context-only surface. |
| G06 | F1 credentials, custody and direct context paragraphs, accepted S3 | Each live record requires one kernel SCM_CREDENTIALS of size 12 matched to actual original sender, expected UID/GID and held identity. Rights count/order, truncation and trailing or unknown ancillary input are checked. Fresh direct context also verifies original peer identity. The inherited sideband relies on original spawn custody and per-record credentials. Structural tests can exercise already classified inputs, leaving kernel acquisition and claims to later gates. |
| G07 | F1 direct context paragraph and accepted S3 wire delta direct evidence rule | The live abstract name is NUL + ASCII `gagamba.va.` + `session32` with exact length and no trailing NUL. F1's reference to the S3 evidence proof supplies the original-session representation context. S3 defines the 32 lowercase `N` digits. Keep this derivation explicit in a future live transport review. Original pins and one-packet drain and half-close on both directions retain their independent evidentiary roles. Live address construction is outside the bounded managed proposal. Common header, types and roles, exact lengths, digest layouts, comparison operands, version/refusal boundaries and live obligations are traceable to named accepted rules. No new wire constant, version, code or authority rule is introduced. The historical F02 draft caption records its preparation state. The F02 owner decision supplies its adoption. Alternative B §3.4 supersedes the original B3 ordering where the two specify different sequencing. Frozen E-3 §§2–5 control the adopted v3-pre and release-boundary details.
