## Decode and compare

Supply one exact record and separate expected exchange operands. Context must identify the expected message, route and sender/recipient, original session/execution/lease, first pending sequence and applicable raw SHA-256 bytes. Premises established by the eventual caller, such as available matched original context, absence of unexpected ancillary input, or prior local checks before ACK, can be represented as synthetic checked inputs for testing. They never create an authenticated result. All four messages are the first and only record in their respective direction on the relevant sideband. Keep the codec stateless. A spent, missing or inconsistent supplied state refuses, with no implicit replay tracking, state advance, recovery or retry. Enforce route consistency with both the type and encoded sender. The recipient is supplied context, outside the wire header.

| Message and source | Valid routes and exact record | Supplied context and comparisons |
|---|---|---|
| 4 INIT, F1 table row 4 and G03/G05 | C→R or R→O, 64-byte payload (128 total), capability SHA-256 followed by catalog SHA-256. Zero rights. | Original parent/child association and pending context. Compare both hashes and the same independently supplied tuple. The future verified INIT precedes effects beyond startup/stop service. |
| 5 CONTEXT-ACK, F1 row 5 and G03/G05 | R→C or O→R, 32-byte capability SHA-256 payload (96 total). Zero rights. | Match original reverse route, the same tuple and capability hash. Catalog provenance remains with the retained INIT/local verified context. ACK contains no catalog field, and absence of the expected established context refuses. |
| 6 DIRECT-CONTEXT, F1 row 6 and G04/G05 | C→O only, 64-byte payload (128 total), capability SHA-256 followed by catalog SHA-256. Zero rights. | Original C/O association and same inherited context. Compare both hashes and tuple against retained original operands. |
| 7 DIRECT-ACK, F1 row 7 and G04/G05 | O→C only, 32-byte capability SHA-256 payload (96 total). Zero rights. | Match original direct peer route and same retained context, tuple and capability hash. No recovery forwarding. Payload contains no catalog field. |

The shared 64-byte header, version 1, LE fields, exact original .NET GUID representation and 128-byte common payload bound follow G01–G02. Enforce exact message lengths before indexing and use bounded arithmetic for hostile declared lengths. Refuse unsupported type, wrong magic/version, invalid role or route, missing/empty original GUIDs, wrong sequence or nonpending context, missing or non-32-byte expected hashes, absent/inconsistent expected original context, malformed length and trailing data. Compare exact bytes or equivalent lossless typed equality. Wrong or contradictory context, malformed input and comparisons yield a bounded refusal and no decoded result, without throwing for the supported malformed-input domain. Local categories may distinguish framing, context/expectation and comparison failures. No assigned wire refusal code or precedence between simultaneous failures arises. Publish only fully checked immutable data. Do not expose input aliases or leak bytes in diagnostics. Verify reusable mutable input and expected/output memory cannot alter retained comparisons.

## Cross-format handoff

Use a data-only comparison between a successful E-3 v3-pre projection, a checked E-4 structural context and independent expected originals. Test composition must call unchanged E-3 R2 with the independently supplied digest and projection, then adapt only the validated fields into E-4's data-only input. The authorized adapter logic may live in the tests. Require the actual accepted E-3 version/topology and `validation-pre` selection. For B2 and integrated, map `Session` and `Execution` to the corresponding GAVA1 GUIDs and root `Generation` to the protocol lease, preserving GUID bytes in existing .NET order. AuthorityHash is the validated 64-literal-lower-hex form of the original capability digest. Catalog SHA-256 stays an independently supplied operand established with INIT and direct context. Store generation, artifact-set and installation digests, qualification associations, and preparation identity are distinct and cannot fill missing GAVA1 identities. A failed E-3 parse or E-4 comparison produces no handoff value. Require disagreement on any one original identity to refuse even when the other values match. Prevent agreeing wire-derived operands from serving as their own independent oracle.

The E-3 adopted §5 release witness uses a 258-byte preimage and preserves the existing 32-byte `ReleaseRequest.ApprovalCorrelationSha256` representation. Show in tests and traceability that the original session/execution/lease and capability/catalog byte identities survive exactly and remain distinct from release, script/action and preparation identities. Use the committed witness as a test-only reference. No shipping release operation, approval bit, recomputation, enforcement, opcode or substitution belongs in the codec.
