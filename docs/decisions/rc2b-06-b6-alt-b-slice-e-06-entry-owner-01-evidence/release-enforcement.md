# ReleaseRequest correlation and enforcement assessment

The wire and formula are accepted; operational enforcement is not implemented. Governing sources: [adopted v3-pre record §5](../../evidence/rc2b-06-b6-alt-b-slice-e-03-v3-pre-frozen-record-candidate-01.md), its [owner adoption](../rc2b-06-b6-alt-b-slice-e-03-qe1-frozen-record-owner-01.md), [E-4 acceptance](../rc2b-06-b6-alt-b-slice-e-04-owner-01.md), F02 case-policy §5 and accepted Alternative B amendment (identities in [provenance](provenance.md)), [plan §§2,3.3,3.5](../../plans/rc2b-06-b6-integrated-start-authority-impl-01.md).

## Exact existing contract

SHA-256 over the following **258 bytes**, concatenated without padding or newline: ASCII `gagamba-validation-release-v1` (29), zero byte (1), capabilityHash (32), Hk (32), Hs (32), A2 (32), little-endian u32 action index 2 (4), original session/execution/lease/preparation GUIDs in existing .NET byte order (4×16), original preparationManifestDigest (32). Raw digests are used, not hex text. Result is 32 raw bytes in the existing `ReleaseRequest` approval-correlation field; the accepted contract's `HasApproval` indication must be true for validation. No new RELEASE opcode, GAVA type or journal schema is needed.

Representation reconciliation: the current `OwnerReleaseRequestWire` has **no separate HasApproval member**. `OwnerHeldWireCodec.RequestFromIdentity(..., correlationPresent)` maps true to a byte array and false to null; `IntegratedB3Client.Release` supplies `!correlation.IsDefault`. Thus current wire presence is a non-null exact 32-byte `ApprovalCorrelationSha256`. Preserve this accepted presence meaning, not an invented JSON Boolean. The integration contract must explicitly trace the normative approval indication through that adapter and reject absent/null/malformed correlation for validation. Ordinary wire parsing permits null; parsing does not enforce validation approval.

| Input | C's independent retained source | O's independently established source / refusal condition |
|---|---|---|
| capabilityHash | Authenticated original L grant retained through B2 | Original inherited sealed capability and local validation context confirmed directly with original C; reject substituted/absent origin even if bytes match |
| Hk, Hs, exact retained case | C's own protected K/S acquisition and immutable case | O's own protected K/M/F/S and exact phase/template; never use request/D policy as expectation |
| A2 and index 2 | SHA256 of action domain tag + zero + exact CJSON1(S.actions[2]) from C-retained S | Independently recompute from O-retained S; exact B3 release template; F/K allowRelease true; no arbitrary script/action/hash input from request |
| original session/execution/lease | Original nonempty C-generated IDs sealed into grant, GAVA and topology | Same inherited/direct-context identities; distinguish root protocol lease from store generation, issuer and preparation IDs |
| preparation GUID and manifest digest | Exact retained PreparedRestrictedExecution object and its admitted manifest | O's own original local preparation/capability identity and exact independently admitted typed manifest; reject wrong generation/execution/preparation/manifest |
| host, boot, selection, original peers | Original context retained separately, not extra hash fields | Independently validate original live C/L/R/O, phase and generation; hash does not attest those observations |

All values must be independently established before computing the expected digest. Self-consistent substitutions of both suspect and expected operands must be detected by upstream binding. Correlation is public binding data, not a secret, approval, live grant or substitute for owner-only capability. C's inspect ordering remains a trusted-C dispatch premise: O proves its own prepare→HELD→optional release→terminal effects, not a remotely attested read-only inspect.

The formula/byte layout needs no new architectural invention. Missing decisions concern native expectation provenance and lifetime, first E-1 consumer, concrete immutable validation context construction and operational refusal/cleanup mapping. Freeze these under their respective contracts; implement the existing formula only as P1 data preparation until authorized integration establishes trustworthy inputs. P1 success must have no conversion to `OwnerAuthorityContext.Validation`, LoadedInstallation, admission, prepared capability or a native handoff.

Future independent controls must mutate each original ID/digest/action index/byte order, false/absent approval, no-release policy, phase/receipt, retained preparation, live peer and deadline independently; test valid digest with wrong independently retained policy; count actual writer attempts; force concurrent duplicate/release/stop and late verifier completion. Test through actual owner/arbiter wiring on the integrated candidate. A pure digest test cannot qualify live release enforcement.
