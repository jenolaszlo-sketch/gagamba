# Dependency-ordered roadmap and single activation boundary

This is a proposed development plan, not implementation authorization. The smallest useful E-6 preparation is P1 below: the accepted release formula and finite-template gate are missing computations whose pure structural behavior can be completed without native authority. Do not create another all-purpose custody simulation or fragment the atomic enablement boundary.

The future authorization should reject the package if those restrictions cannot be met with the two-file scope.

| Fresh P4 review and separate owner acceptance | No; P1 still needs its own isolation controls | Candidate can be produced, not accepted/exposed | Independent audit must be completed | Yes |

The circular-wait solution is development behind refusal, contract-first resource boundaries, E-6/E-7 co-assembly, then separately authorized exact-candidate qualification, then exposure. It is not enabling E-6 so that E-7 or Slice N can catch up. Real A approvals must follow actual independently reviewed candidate/case bytes; unqualified earlier evidence cannot approve itself. Pre validation does not require final qualification, so the acyclic pre→qualification→fresh post chain is retained without fabricating S2 or final admission.
