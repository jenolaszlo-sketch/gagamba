## Potential bounded package after the decisions

The smallest candidate for reassessment is an internal, unreachable managed launcher/controller and custody **contract** seam, with test-only fixture operands, a neutral refusal/result, original identity binding and independently derived expectations. Its positive witnesses represent structural contract success only. Proposed scope would keep existing codec, E-1, P4 and production entry-point code fixed, with no new production caller or authority constructor. Exact production and test files depend on the owner-approved seam. No implementation file allowlist is proposed for authorization at this gate. Native fixed-loader work, protected reads/provisioning, OS transport, dispatch, data acquisition from live actors, first E-1 consumer, issuance/approval, journal/writer/staging/release and changes to sandbox providers require separate decisions or stay outside that candidate.

The confirmed platform prerequisites for a **real** invocation are Linux trusted host-root and initial user namespace, reviewed procfs/time/PID namespace and monotonic boot identity, protected fixed installation and stable file reads, permanent privilege drop and readback, original pidfds and verifiable spawn custody, kernel peer and per-record credentials, bounded sequenced sideband and sealed descriptor properties. Accepted exclusive pinned child acquisition is allowed only under its specified no-reaper/ambiguity conditions. Installed topology and delegation checks remain applicable to their respective paths. Portable managed verification can exercise stipulated results and deterministic fail-closed behavior. Actual platform support, protected-root integrity, root/peer provenance, mounted closure, cleanup, and bounded stopping demand separate integration and native evidence. Windows module availability is unrelated to these Linux prerequisites.
