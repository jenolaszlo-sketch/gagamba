# F02 conflict analysis and compatibility assessment

## Inherited requirement

`ValidationReachabilityTests.ValidationMemberNamesDoNotImplyAuthority` obtains types from the compiled assembly containing `FrozenContractVerifier`, selects the exact namespace `Gagamba.Execution.Linux.M1.Validation`, and checks each type name and each declared member name. Reflection uses public and nonpublic, instance and static, and `DeclaredOnly` flags. The substring test is ordinal and case-sensitive for `Approved`, `Authorized`, `Permit`, `Authority`, `Trusted` and `Capability`. The rule covers internal members and private nested types in that namespace, including compiler-generated members. It preserves the authority-neutral vocabulary of the E-2 structural core. The companion export, dependency and caller checks address other properties of the boundary. E-2's direct-call-only scope and first-consumer qualification remain as accepted. P2's separate test for specified detached-evidence types and its longer vocabulary also retain their original scope. ## Exact cause and naming proof

The baseline F01 test passed in Debug and Release. The exact candidate's test failed in each configuration with the `Capability` token. The audit read the manifest-bound XML, logs and compiled inventories. It separately inspected both retained producer core assemblies, rechecking their SHA-256 against the selected-copy receipts. Each inspection covered 28 types and 859 declared members. The seven matches came from two declarations:

- `ValidationReleaseProjection.CapabilityHash` emitted the property, getter and backing field.
- The `CapabilityHash` positional slot of `ValidationReleasePreparation.Binding` emitted a property, getter, init setter and backing field.

The Managed API section originally required the first spelling. The second spelling is a private copied representation of the same input. The invariant tests member names directly, so the old spelling is sufficient to fail even though the candidate's helper has no production caller. Constructor and deconstruction parameter names are not member names under this test but are included in the exact mapping. Projecting the seven renamed names in memory against the full unchanged vocabulary yielded zero matches and no collision in either artifact's namespace inventory. The check generated no replacement DLL and ran no remediated tests. ## Provenance and equivalence

The case-policy release formula, Alternative B amendment and adopted E-3 §5 use the raw `capabilityHash` input. The E-6 release assessment traces it from the authenticated original L grant retained by C and independently tied to O's original inherited sealed data and local context. The accepted mechanism distinguishes the complete canonical launch record in the sealed memfd from its transport descriptor, credential evidence and separate catalog hash. `SealedLaunchRecordHash` says which record supplies the digest, while keeping custody and provenance outside the structural helper. The property is distinct from `CatalogHash`, `ScriptHash`, `ReleaseActionHash` and `PreparationManifestDigest`, and does not denote a boot identifier, launcher executable hash, preparation digest or hash of the whole release preimage. [Adopted formula](../../evidence/rc2b-06-b6-alt-b-slice-e-03-v3-pre-frozen-record-candidate-01.md) · [Original input associations](../rc2b-06-b6-alt-b-slice-e-06-entry-owner-01-evidence/release-enforcement.md) · [Custody and operand lifetime](../rc2b-06-b6-alt-b-slice-e-06-entry-owner-01-evidence/live-custody.md)

The source has one use of this digest in encoding, `binding.CapabilityHash.CopyTo(bytes[30..62])`, after independent input validation, bounded copy and byte equality. The replacement changes the identifier at those same reads and writes. The audit reconstructed both full preimages and their SHA-256 values independently and matched the exact test literals. The same slot remains `11` repeated 32 times in R01, and `00` through `1f` in the mixed vector. R02 still differs in the separate expected digest and retains `DigestMismatch` with null output. The rename preserves every input width and association, domain and zero separator, LE action index, GUID byte order, ordering, offsets, result widths and refusal precedence.
