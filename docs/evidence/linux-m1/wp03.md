## 2. Delegation and preflight

- cgroup2 mount: `/sys/fs/cgroup`, fs type `cgroup2`, mount ID `356`,
  options include `nsdelegate`. Read from `/proc/self/mountinfo`; never a
  supplied string.
- Boot ID: `/proc/sys/kernel/random/boot_id`
  (`5a6f8a5a-c5ab-4738-b337-d1cf4e29a770`).
- Root cgroup `cgroup.controllers` = `cpuset cpu io memory hugetlb pids rdma`;
  `cgroup.subtree_control` = `cpu memory hugetlb pids rdma`.
- Operator-provided delegation: the harness creates a parent and enables
  `+memory +pids` in its `cgroup.subtree_control`, so the child domain
  gains `memory.max`, `memory.swap.max`, `pids.max`, `cgroup.kill`,
  `cgroup.events`. WP03 never configures host delegation; missing
  delegation/controls refuse (proven by `MissingDelegationRefused` and by
  the fail-closed `memory.max open errno 2` observed before the harness
  enabled controllers).
- pidfd/subreaper: kernel 6.6; `PR_SET_CHILD_SUBREAPER` set and read back
  verified (`SubreaperEnabledAndVerified`). No host configuration changed.

## 3. Stable domain identity

`DomainIdentity{ ExecutionId, BootId, CgroupMountId, CgroupMountFsType,
ParentDevice, ParentInode, ChildName, ChildDevice, ChildInode,
LeaseGeneration }` plus the live handles held by the backend. Mount
identity comes from the real mount; parent/child resolution is
beneath-only, no-follow (`RESOLVE_BENEATH|RESOLVE_NO_SYMLINKS|
RESOLVE_NO_MAGICLINKS`). `Corroborates` compares every field but the
handles; `SameNameButReplaced` detects a same-name different-inode swap.

## 4. Allocation ordering and pre-opened controls

Order: persist `AllocationIntent` → generate fresh child name → `mkdirat`
under the retained parent → open+stat the domain dir → capture identity →
open controls → verify each control's device matches the domain dir →
build identity. Pre-opened: domain directory, `cgroup.kill` (O_WRONLY),
`cgroup.events` (O_RDONLY), `memory.max`/`memory.swap.max`/`pids.max`
(O_RDWR). WP03 installs no limits (WP06). `EEXIST` on the child name
refuses; nothing existing is adopted.

## 5. Whole-domain stop and identity-checked removal

Stop writes `1` through the retained `cgroup.kill` handle and polls the
retained `cgroup.events` handle for `populated 0` with a bounded deadline
(25 ms interval). No PID enumeration, no journal PID kill, no pathname
re-open. Removal re-looks-up the child under the retained parent,
requires the exact captured dev/ino, then `unlinkat(AT_REMOVEDIR)`. A
same-name replacement refuses removal and reports Unknown.

## 6. Journal format and durability

Bounded little-endian snapshot, version 1, ≤64 KiB, ≤128 allocations,
sequence-monotonic, SHA-256 checksum over the payload. Fields: version,
sequence, execution id, boot id, cgroup mount id/fs, parent dev/ino,
domain name/dev/ino, lease generation, writer kind, cleanup state,
preparation stage, bounded allocation inventory, optional recorded
preparation identity. Excluded: release credentials, release writer,
secrets, raw input, unbounded logs. Durability: exclusive temp create →
complete write → file fsync → atomic rename → directory fsync; the prior
complete snapshot survives any failed replacement (proven). Writer
exclusivity is a `flock` held for the journal lifetime; the kernel
releases it on process death, which makes takeover a fence.

## 7. Bootstrap FD-role map

The owner accepts only an inherited private bootstrap with exact
versioned roles, each once, nothing else:

| Role | Native mapping | Direction |
|---|---|---|
| ControlRead | inherited stdin (fd 0) | scope→owner |
| ControlWrite | inherited stdout (fd 1) | owner→scope |
| RecoveryEvidence | inherited stderr (fd 2) | owner→scope |

No release authority, named listener, filesystem socket, reconnect API or
serialized bearer token exists. Validation rejects wrong version, missing,
extra, duplicate and negative descriptors.

## 8. Writer transfer

The scope writes allocation/bootstrap snapshots; the owner acquires the
`flock` writer lock after validating bootstrap (observed as
`WRITER_LOCKED`). One writer at a time; a second lock attempt in another
process fails (`NativeWriterLockIsExclusiveAcrossProcesses`). Recovery
takeover after owner death re-acquires the fence (kernel-released) before
rewriting results.

## 10. Owner-death and recovery cases

Natively proven (real owner process, real cgroup):

- `OwnerDeathBeforeOpenLeavesDomainForScopeRecovery` — owner exits before
  opening the domain; the scope's recovery duplicate stops, empties,
  identity-checks and removes it.
- `OwnerBootstrapsAcquiresLockThenDiesAndScopeRecovers` — owner validates
  bootstrap, acquires the writer lock, then dies; scope fences and cleans.
- `ReplacementBlocksRemoval`, `UnrelatedSiblingUntouched`,
  `SuccessfulDomainAllocateStopRemove`, `RetainedControlHandleIdentityIsStable`,
  `CgroupMountAndBootIdentityAreReadable`, `MissingDelegationRefused`,
  `NativeJournalDurableThenTornDetected`,
  `NativeWriterLockIsExclusiveAcrossProcesses`.

Portably proven (deterministic fakes):

- cross-boot refusal, restart-only quarantine, mismatch refusal,
  destructive cleanup only with live corroborated authority, cleaner
  failure, replacement refusal, idempotence (`ReconcilerTests`).
- identity mismatch, stop timeout, kill/read faults, removal refusal,
  independent recovery duplicates, disposed lease has no authority
  (`DomainLeaseTests`).
- journal bounds/version/sequence/checksum, torn detection, each
  durability step, prior-snapshot survival, writer fencing
  (`JournalTests`).
- bootstrap allowlist (`OwnerBootstrapTests`).
- integrated ordering (`PreparationOwnershipTests`).

## 13. Limitations and nonclaims

- Native owner-death barriers proven: before-open and after-lock. The
  remaining barriers (pre-intent, post-intent/pre-create,
  post-create/pre-register, post-register/pre-ack, post-ack/pre-transfer,
  immediately post-transfer, pre-Prepared, post-Prepared/pre-Mint,
  cleanup-in-progress) are covered by portable ordering/fault tests, not
  each by a distinct native kill.
- Subreaper set/readback is verified and the owner is reaped as the
  scope's direct child; deeper adopted-grandchild reaping is not
  separately proven in this pass.
- Recovery cleans accounted allocations through retained handles; a full
  native WP02-staging recovery walk is covered portably and by the
  integrated coordinator, not by a distinct native crash of a staged
  preparation.
- WP03 owner holds no domain authority; domain authority stays with the
  scope and its recovery duplicate (conservative for these states).
- No Bubblewrap/coordinator/release/target work (WP04+); no production
  admission; no host reconfiguration; restart with only records yields
  Unknown/quarantine and requires operator handling.
