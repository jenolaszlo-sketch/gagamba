## Observed startup incompatibility and policy delta

The prior 424-byte x86-64 filter had raw SHA-256 `3649a083435cb7e7f1dad0157dfe6bd4c480ad635b7cecb88214a9332403395c`. Its clone-tail JSET disposition returned `EPERM` for the following demonstrated trusted startup operations. The diagnosis used a bounded syscall trace of Bubblewrap launching the trusted coordinator through pre-HELD startup; no target execution was used. The original trace files lived in the prior WSL boot's temporary filesystem and were lost when that distro stopped; the observed syscall identities and arguments are retained here.

| Syscall | Observed operation and location | New narrow rule |
|---|---|---|
| `158 arch_prctl` | Dynamic loader TLS setup before coordinator `main`; `ARCH_SET_FS` (`args[0]` low word `0x1002`). | Allow only `ARCH_SET_FS`; other `arch_prctl` operations remain `EPERM`. The FS-base argument remains the value being set. |
| `157 prctl` | Coordinator startup calls `PR_SET_DUMPABLE(0)` before HELD (`exec-coordinator.c` startup hardening). | Allow only option `4` with the complete second argument equal to `0`; other `PR_SET_DUMPABLE` values and other `prctl` operations remain `EPERM`. |
| `157 prctl` | Coordinator HELD reporting calls `PR_GET_DUMPABLE`; the previous filter returned `EPERM`. | Allow only option `3` with a zero high word for the option. The kernel ignores later arguments for this query. Other `prctl` operations remain `EPERM`. |
| `436 close_range` | Coordinator closes descriptors from `6` through `UINT_MAX` with flags `0` before validating its control/status descriptors (`exec-coordinator.c` descriptor setup). | Allow only the full 64-bit tuple `(6, UINT_MAX, 0)`; all other argument tuples remain `EPERM`. |

The policy source of truth is `native/linux-m1/seccomp_filter_policy.py`, generator version 4, Python standard library, x86-64 classic BPF. The generated raw filter is 672 bytes with SHA-256 `4ee63c48010d74118f74ddec44b48acc16cabc3e7e5693e83d941f82bbb3a2bc`. The generator regenerates `native/linux-m1/seccomp-filter.hex`; the native build verifies that output and the pinned length/hash before building artifacts.

The changes add only the constrained operations above. Existing architecture/x32 rejection, explicit syscall denials, clone namespace restrictions, `clone3` denial, and the preserved default disposition remain covered by policy regression tests. No unrestricted fallback, target release path, or namespace/mount/ptrace/credential authority was added.
