## Section 11 authority

The implementation plan defines exact internal fixture-envelope ceilings: private `/tmp` tmpfs at 7 MiB (7,340,032 bytes) and private `/dev/shm` tmpfs at 1 MiB (1,048,576 bytes), aggregate 8 MiB, with no third writable file store. Both values are page-aligned on the qualified host. Section 11 requires the expected capacity to be read from `statfs` and the established tmpfs `size=` option; the option is a ceiling, so its semantic byte value must equal the configured value.

The scratch mounts must be writable, private tmpfs mounts with `nodev` and `nosuid`. Section 11 does not require or claim `noexec` for scratch. The observed mount mode was 0755; the plan does not assign distinct contractual mode bits to `/tmp` and `/dev/shm`.

`BubblewrapArguments.Build()` requests `--size 1048576 --tmpfs /dev/shm`, then `--size 7340032 --tmpfs /tmp`, and remounts `/` read-only after creating the child mounts. The construction order and numeric byte requests matched the Section 11 contract.

## Root cause and remediation

**Classification:** verifier bug plus unit/normalization bug. This was not a Bubblewrap construction error, coordinator report error, wrong-namespace selection, or invalid Section 11 assumption.

The verifier compared a byte-valued configuration against kernel mountinfo text as if the kernel had to preserve the original spelling. It did not parse the kernel's `k`, `m`, or `g` suffixes into bytes. R3 now performs overflow-safe semantic parsing and requires exact equality with each independent Section 11 ceiling. Missing, duplicate, unsupported, malformed, overflowing, undersized, and oversized values fail closed.

The verifier also parses mount IDs, parent IDs, backing device, root, mountpoint, filesystem, source, mount options, optional propagation fields, and superblock options. It requires the exact expected mount tree; `/tmp` and `/dev/shm` must be separate root-backed tmpfs mounts directly parented by the sandbox root, must not alias one another or any host-visible filesystem device, and must retain `rw,nodev,nosuid`. The adapter compares the trusted coordinator's six reported namespace inodes against its own `/proc/self/ns/*` identities and refuses an inherited host namespace.

No HELD wire-format, native coordinator, Bubblewrap argument, R1 reaper, R2 seccomp/filter pin, or wrong-architecture kill-atom change was made. The HELD mountinfo was corroborated by a read-only host observer during the held state; the target fixture was never released or executed.
