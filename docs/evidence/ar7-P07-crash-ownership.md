## Question and mechanism

Can the surviving setup topology guarantee that failures during setup, release, execution, cancellation, and teardown never produce a target that is both released and no longer lifecycle-owned — while preserving truthful distinction between target-root completion, wrapper/helper completion, and loss of observation?

Executed design: `docs/reviews/2026-10-10-ar7-p07-design.md` as approved with the three review clarifications (controller-owned check→commit barrier with pre-exec re-check; observer as enforcer+oracle with authority proof and C11; owned-survival vs unowned-failure semantics). Ordering authority was the manager state machine; monotonic timestamps were single-domain evidence only (no mtime comparison anywhere); stops used `cgroup.kill` + `populated` polling only. Correction (independent review M6): the 70cf run recorded starttimes but did **not** re-compare them immediately before fault injection (C10 slept 0.5 s post-resolution; C6 scanned-then-signaled), and the `validate_pid()` helper was unused. Per-action revalidation was added in remediation (`signal_validated`: refuse-absent/refuse-mismatch/signaled) with c6/c10 reruns and the `r6stale` guard demonstration — see remediation section. Fault-injection kills are the test itself, never a stop mechanism.

## Replacement R2 (phase-proven pre-target deadline)

The re-review's sole execution blocker was R2 phase proof: the old `af61…` run showed an early kill with no target output, but could not prove target initialization never began. The replacement uses a committed test-only pre-target exec gate — instrumentation, not a new mechanism: Bubblewrap launches the gate as the namespace root under the identical namespaces/cap-drop/seccomp/cgroup/ownership composition (one documented fixture-preparation delta: an extra `--ro-bind` of the gate binary alongside the unchanged `/target` bind; the gate itself enforces nothing). The gate records nonce-bound `PRETARGET_GATE_REACHED`, blocks on the controller-owned stdin channel, performs no fork/spawn/exec while blocked, `execve()`s the actual target only on the exact expected nonce, and echoes any received bytes as `AUTH_RECEIVED` first. Correction (R2 replacement review): for THESE in-worker runs the documented extra `--ro-bind` did not exist - COMMON was unchanged, so the gate was a mode inside the already-initialized worker, not a pre-initialization barrier. These runs are retained as authorization-controlled re-exec/useful-work and held-worker domain-stop observations only; the phase claim is withdrawn. Harness: `bd96d5f` (gate + runner), corrected by `bca5690` (barrier-free `spinwork` post-release workload; the first positive `1b93…` is preserved as `superseded-r2pos-1b93…` — its gate released correctly but the chosen sleeper workload read EOF on the manager-closed stdin (go_read rc=0, exit 126, timeout false) - a harness workload defect, not a gate defect and not a deadlock).

- Positive (`r2-r2pos-7878…`, source `bca5690`): full pre-decision snapshot (manager + 2×bwrap + gate, states/starttimes/cmdlines/cgroups; no non-gate target process; gate cmdline still gate); exact-nonce auth sent after the proven gate; gate echoed receipt and execved; target initialized post-release (`spinwork_sum` + `complete`, rc 0, useful bounded work); domain empty; cleanup confirmed.
