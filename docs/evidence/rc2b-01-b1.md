## Actual scope and material adaptations

Authority: RC-D04/D05/D07, RC1-A qualifications, RC2A-04 owner acceptance and the
explicit B1-only owner work order. RC2A-04 remains ACCEPTED WITH QUALIFICATIONS.

The operational public path is **safe refusal**: `RestrictedExecutionRuntime.Create()`
returns a separate `IRestrictedExecutionProvider`; known experimental/production
profiles refuse `InstallationUnavailable`, unknown profiles refuse `UnsupportedProfile`.
Selection allocates no domain, staging, owner, source handles or native resources.
Inspection returns Unavailable; reconciliation explicitly refuses recovery authority
with Unknown cleanup. There is no ordinary-provider adapter, fallback or bypass option.

All descriptor fields required by D04 have a public place: provider/implementation,
contract/provider package versions, source commit/tree, RID, schema/owner/coordinator
protocols, artifact inventory/hash and qualification identity/scope. B1 has **no installed
descriptor**: those installation facts are null/absent, not invented binary pins or
versions. `ContractPackageId` and `gagamba-restricted-control-v1` identify the contract,
not a deployed artifact. Qualification is split into ID and scope; the original
`Qualification` sketch does not define a wire structure. No successful installation
constructor/registration or deployment-manifest grammar is added. B6 must review those.

The bounded selection contains profile/version/RID/qualification ID and the digest
of exact retained artifact-inventory bytes. These are caller evidence, not attestation.
Preparation inputs contain bounded enrolled source IDs only, with no path, manifest,
readiness, native handle or caller deadline. Invalid arguments reject synchronously
before operation/resource creation. All-zero digest is valid present data.

Operation, prepared view and provider-origin results have no public constructors.
The internal owner seam has **no production implementation and no physical release
method**. Only deterministic tests instantiate it, using explicitly synthetic manifest,
receipt and clock data. That is contract testing, not a successful live preparation stub.
There is no public route to those synthetic preparations. Before publication, the local
operation checks descriptor object, digest, generation and cached owner issuance liveness;
release observation checks the exact operation/prepared object and copied five-field
identity. Native store, copied-source, handshake and arbiter checks remain B3 obligations.

Pre-retention release always refuses `LiveReleaseNotImplemented` with binding Unknown
unless an earlier binding/stop/disposal check refuses. It admits **no** correlation and
retains **no** new release decision. This global unwired boundary is not a choice of
nonconsuming mismatch semantics. A cached existing owner decision projects as Duplicate
with original facts and separate Accepted/Mismatch/InvalidArgument binding status,
including after stop/disposal; this is observation, never a new release attempt.

## R1-F02: implemented local winning-order contract

The operation's short in-memory gate orders **local stop latching versus capability
publication**. No owner I/O occurs under it. Cached owner getters must be nonblocking.
The first stop is observable as LocallyQueued even if an ACK completes immediately;
observation/repeated stop can subsequently show RuntimeAccepted or Unknown. Only a
separate actual runtime acceptance could assert C2 consumption. B1 does not assert it
from queueing. First cause and any original accepted times are retained, never renewed.

| Stop timing | Observable contract and winning order |
| --- | --- |
| Before preparation | Latch first; Prepare returns CancelledBeforeRelease; no owner preparation call or minted view |
| During preparation, before publication | Latch does not wait for preparation; late successful reply cannot publish a prepared view |
| Concurrent with publication | The local gate orders the two. Stop first prevents publication. Publication first may return a view, but the stop latch then inhibits its release immediately |
| Prepared, before release | Immediate local inhibition; delayed/lost owner ACK cannot restore authority |
| Concurrent with release | B1 submits no release at all: refusal can precede stop or report StopRequested after the latch. Actual owner release/stop ordering is still C1/C2/C4 and B3 qualification, not proven by these tests |
| After retained release decision | Keep the retained original decision; later valid same-instance calls are Duplicate with separate binding status, regardless of stop. Stop cannot erase earlier release/ambiguity facts |

Repeated stop submits to the owner seam once. Cancellation of a stop wait still queues
the obligation; cancellation of a preparation wait retains the original task and does
not reprepare. Ambiguous prepare/stop replies remain Unknown without retry. Disposal
inhibits release, queues stop and retains actual cleanup evidence or Unknown; completed
`DisposeAsync` alone establishes no cleanup. The two deterministic publication orders,
blocked preparation, delayed/lost ACKs, invalid issuance and disposal are tested.

This resolves the local contract implementation portion of R1-F02, pending independent
review. The finding is **not closed for native/runtime enforcement**: real C2 consumption,
stop persistence failure, process loss, owner/scope survival and the native release gate
remain independently qualified obligations. Existing C1/C2/arbiter tests are regressions,
not fresh acceptance of those workstreams.

## R1-F03: proposed decision; OWNER APPROVAL REQUIRED

**Recommendation A:** refuse only the mismatching pre-retention call, without retaining
a release decision, replacing the first admitted correlation or consuming capability.
A later matching call may be admitted only under unchanged liveness/deadline/C1–C4
rules. Never automatically retry or create a second physical release. This follows the
recommendation preserved in independent RC1 review `feb9d7584c41712195d4b90754ed7a342ba74bb7`;
RC1-A expressly did not approve it.

**Alternative B:** make such a mismatch terminal for local admission, retaining refusal
and/or invalidating the operation with explicit stop. This must still preserve any
winning owner release and C1/C2 first-retainer facts. It is more fail-closed on correlation
conflict, but a mistaken or competing trusted caller could deny an otherwise valid
operation. It does not retrospectively prove that an in-flight target did not execute.

A preserves liveness and avoids a mismatch-induced denial of service while granting
no authority to the conflicting caller. It tolerates repeated bad requests and relies
on the trusted-host access boundary and unchanged arbiter for at-most-once delivery.
B reduces further admission after conflict at the cost of that stronger denial-of-service
surface. Neither is authorization to change journal formats or accepted C semantics.

Proposed A table (not executed by the B1 release path):

| Request / timing | Proposed effect | Later matching request |
| --- | --- | --- |
| First valid absent or exactly-32-byte correlation | Atomically admit the first binding; all-zero is present. No replacement and no durable-correlation claim without evidence | Ordinary existing release gates apply |
| Matching repeat before retention | Existing C4 concurrency/pre-gate rules; may return Refused while another caller wins. No wait-for-winner protocol, no new physical attempt | No restored authority or extended deadline |
| Mismatch before retention | Refuse this call with binding Mismatch; retain no new release decision and consume no state because of this mismatch | Original correlation remains binding |
| Matching request after mismatch | Eligible under original gates only; no priority, reprepare or implied replay permission | May proceed only while still live/unused and no retained decision/in-flight exclusion forbids it |
| Mismatch after retained decision | Duplicate plus original decision/correlation and separate binding Mismatch; never replace C4 facts | Remains Duplicate |
| Concurrent matching and mismatching requests | First admitted binding stays; mismatch has proposed A's local refusal only. Matching caller still obeys C4 and C1/C2 first-retainer ordering | No caller serialization or second physical delivery |
| Lost response, cancelled wait, explicit replay | Cancel only the wait; inspect available evidence. Retained calls return Duplicate; unknown ACK never authorizes automatic retry, renewed time or new capability | An explicit invocation still faces original gates; ambiguity cannot be retried |

Already-fixed tests: 0/31/33-byte correlation refusals; default absence versus present
all-zero; matching/mismatching/invalid requests after retention; concurrent retained
matching/mismatching projections; original Refused/Released/Stopped/AmbiguousPersistence
decisions; no automatic physical replay. **No tests claim A or B was implemented before
retention.** The closed release gate admits no first correlation in B1.

Exact owner choice needed: **Does pre-retention mismatch leave admission/capability and
release-retention state unchanged, permitting a later matching request under existing
gates (A), or make the operation terminal/consuming (B)?** Record that explicit decision
before implementing the dependent release-admission code. No new durable journal field.
