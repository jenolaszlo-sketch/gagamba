Startup checks unprivileged Linux x64/arm64, distinct inherited SOCK_SEQPACKET roles,
SO_PEERCRED expected parent PID/UID, CLOEXEC, zero parent-death signal, successful
`setsid`/session/process-group readback, retained CLOEXEC controller pidfd, and M1
subreaper enable/readback. Descendants are created only afterward. A supplied delegated
parent must pass existing M1 cgroup2/memory/pids checks; no delegation is provisioned.
Recovery and owner remain outside their uniquely allocated target-domain child.

Observed tree: test supervisor -> controller -> recovery (new session/subreaper) -> owner.
After controller SIGKILL, the supervisor adopts recovery, which remains alive with its
own sockets, pidfds and optional delegated/domain handles. The test supervisor is only
an observer/cleanup parent; all recovery loss detection and stop decisions execute in
the Recovery DLL. Neither supervisor callbacks nor controller cancellation drive stop.

This B2 commissioning host has a fixed 30-second lifetime bound; the owner fixture has

A stalled/unknown owner is not converted to successful cleanup. The two-second volatile
stop-obligation deadline is retained once in Stopwatch ticks and never renewed; it is
not a sealed C3 StopRecord, renewed recovery allowance, or proof of stop enforcement.

Deployment assumption: no external supervisor kills recovery together with the controller.
`setsid`, parent-death checks and actual survival qualify the tested SIGKILL/EOF topology;
they cannot attest arbitrary shared cgroup/job/process-tree supervisor policies. B6 must
qualify each installed layout. No production operation is admitted by this internal host.

## IPC, authentication and authority

`GAGAMBA_B2_CONTROL_FD` and `GAGAMBA_B2_CREDENTIAL_FD` contain descriptor numbers only.
Both roles must be different sockets/inodes, inherited from the expected controller;
SO_TYPE and SO_PEERCRED are checked. Recovery marks both CLOEXEC, removes their environment
entries, consumes/closes the credential channel, and never passes them to the owner.
A bootstrap-created cryptographic random 32-byte secret travels only in the private
credential record. Association presents session UUID plus secret on the separate control
socket. Exact execution/generation identities and monotonically ordered per-direction
sequences bind the versioned frames. Authentication is single use with constant-time secret
comparison; known secret buffers are cleared. No secret appears in argv, environment values,
journal, evidence, diagnostics or target input. Hostile same-UID code and administrators
remain outside this trust model; this is not same-UID isolation.

Bootstrap JSON: version 1, at most 8192 bytes/depth 12, unknown properties refused.
Controller wire: distinct magic `0x4d314f70`, version 1, existing 48-byte M1 framing,
at most 512 payload bytes; invalid shape/version/identity/sequence fails closed.
The shared bounded SCM_RIGHTS receiver closes unexpected descriptors and rejects truncation.
No named reconnect endpoint exists. Reconnect and duplicate association are explicitly
refused and initiate stop; no release-capable generation can be reconstructed.

Control sends are nonblocking. Controller pidfd and owner lifeline polling continue
independently of observers. No capture traffic exists in B2. First stop emits at most
one owner stop request, or closes the owner lifeline on delivery failure. Lost ACK remains
unobserved; a later owner exit never fabricates acknowledgement or native enforcement.
EINTR/EAGAIN observation errors are transient, not peer death; send uncertainty is never retried.

Owner protocol version remains 1; isolated B2 types 23-26 have fixed payload shapes and
no descriptor transfer. The `--b2-lifeline 1` mode never creates a PreparationStore,
capability, release writer or target. It retains a recovery pidfd and responds to EOF/death
or a stop frame with a fixture-only stop observation and exit. Normal owner preparation
remains on the existing transaction path.

With the optional delegated parent, the host instead reuses `StartOwnerPreparation` at
`after-domain-retained`, before AllocationRegistered/copy/Prepared/Mint. Its manifest
callback throws if reached. Existing transfer validation retains the real DomainLease.
Stop verifies retained identity, writes the retained kill descriptor, observes population,
and closes the original owner lifeline. Removal requires pidfd-proven exit and existing
identity-checked removal. No journal-writer takeover or B5 reconciliation occurs.
The leftover AllocationIntent is not rewritten as a completed journal or successful cleanup.

There is no preparation/release request, capability factory, release retry, public
registration or passive-record adoption in this slice. `UnavailableRestrictedExecutionProvider`
remains the default. Execution/Runtime production source, schemas, vectors and native C
sources are unchanged.
