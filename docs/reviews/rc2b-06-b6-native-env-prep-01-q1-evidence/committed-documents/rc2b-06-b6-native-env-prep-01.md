## 7. Minimal delegated cgroup authority

Use a single systemd-managed delegated service in the new distro with `User=gagambaqual`, `Delegate=memory pids`, and a separate supervisor leaf. The unit's actual ControlGroup path, boot ID, cgroup2 mount ID/device/inode and UID/GID are recorded; never guess the runtime parent from a unit name. The operator owns its outer resource envelope. No rights above the delegation boundary, to unrelated processes, or to the host cgroup root are granted.

Proposed topology: service boundary `P`, supervisor in `P/supervisor`, empty domain parent `P/domains`, per-execution children under `P/domains`. Enable memory+pids down the empty interior hierarchy, before admission. Kernel no-internal-process rules require moving the supervisor into its leaf before enabling controllers. The delegater must place the first process; the unprivileged user cannot bootstrap itself across the boundary. Use `DelegateSubgroup=supervisor` only after verifying support in the selected systemd (introduced in254), or a separately reviewed operator placement mechanism before controller enablement. `User=` plus `Delegate=` alone does not place the service in a leaf; missing placement is an explicit P05/N2 stop gate. The service must remain alive through controller death while original R/O stopping/reaping completes; do not let a short-lived scope exit erase the evidence.

Permissions: dedicated UID can create/remove its own children; traverse/read the retained parent; read controllers/subtree controls, child cgroup.events/cgroup.procs and limits; have `cgroup.procs` write permission on its target child and the common ancestor with its spawning supervisor for kernel atomic-placement authorization; write only its created child `memory.max`, `memory.swap.max`, `pids.max`, `cgroup.kill`. Child `cgroup.kill` is write-only access in CgroupInterop; requiring a read-open would be wrong. Runtime code does not write cgroup.threads or enable controllers: the operator pre-enables the selected subtree, and no additional thread-migration/controller-reconfiguration grant is requested. Record any structural permissions inherent in systemd delegation and prove they remain inside the dedicated envelope; do not present systemd defaults as a narrower authority than they supply. Although Gagamba only reads cgroup.procs directly, atomic clone placement still checks its write permission at the target and common ancestor ([kernel implementation](https://raw.githubusercontent.com/torvalds/linux/master/kernel/cgroup/cgroup.c)). Parent resource limits remain operator-controlled; do not recursively chown the hierarchy or its parent's resource controls. Record actual mode/ACL rather than assuming cgroup file defaults. The source requires both memory+pids in `cgroup.controllers` and `cgroup.subtree_control`; children must expose swap accounting.

The fixed target envelope is **memory.max=134217728, memory.swap.max=0, pids.max=48**, with exact write/readback before atomic spawn (`CgroupInterop.cs`, `B3Qualification.cs:415–417`). A separate outer service envelope includes managed C/R/O and supervisor; the target's 128 MiB is not the whole environment budget. Retained domain/kill/events/readback descriptors, boot/mount/inode identity, cgroup.procs membership, populated=0 and reaping evidence govern recovery and removal. Missing readback or uncertain ownership stays Unknown.

The [kernel delegation rules](https://cdn.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) constrain migration at the common ancestor. [systemd delegation guidance](https://github.com/systemd/systemd/blob/main/docs/CGROUP_DELEGATION.md) explains the controller and leaf requirements. The future operator must inspect the generated unit and permissions and prove a child cannot affect an unrelated synthetic outside cgroup. A root process in Docker or a user namespace proves neither delegation nor this boundary. Qualified B2's forbidden delegated-parent topology remains forbidden even though B3 and legacy v1 need delegation.

If the selected record schema/scope demands tests that cannot run until publication, require a bounded owner-approved staged qualification protocol before execution; do not self-attest completion or use a full-pass record to unlock tests. Postpublication results cannot retroactively justify an untrue earlier record.

`/etc/gagamba/accepted-qualifications` controls **publication**, `/opt/gagamba/qualifications` contains the **receipt-selected runtime record**. Do not merge them. Withdrawal prevents subsequent publication/retry, after serialization with any in-flight qualifier; it does not revoke an already published record or remove admitted stopping authority. No revocation semantics are added.

## 9. Resources, operational limits and teardown

Prefer D: because the observed C: free space is small. No measured fresh-image/package/build peak exists. Budget disk as image+installed packages+package cache+source+build outputs+two candidates+retained generations+logs+evidence export+headroom. Source verifier bounds are <=32 MiB/artifact and <=128 MiB total candidate artifacts, <=256 KiB metadata, <=32 verifier files/8 directories/8 depth; runtime inventories separately permit up to2048 files. These are input limits, not expected disk sizes. Native fixture target memory128 MiB/tasks48/shm1 MiB and capture bounds are source constraints, not sufficient guest memory estimates.

Measure a single authorized serial build/probe before choosing the outer memory/task ceiling; reserve room for C/R/O, test runner and independent watchdog. Current ~2.17 GiB Windows free RAM is insufficient evidence of build headroom. Schedule when memory is available, avoid concurrent Docker load by owner-controlled scheduling, and stop on measured pressure. Do not terminate Docker or edit global `.wslconfig`. No precise package footprint, minimum RAM, total process peak or log volume is asserted without measurement. Bound fixture output, retain JSONL/journals/TRX and hashes, cap tracing by selected finite scenario/time and preserve untraced timing separately. If serial local work cannot fit, defer it or obtain a separate scope decision for a suitable machine; no cloud purchase is needed by this plan.

Teardown begins by stopping **new admission through the qualification supervisor**, not by deleting `active` or changing runtime revocation rules. Enumerate admitted generation/lease/session IDs and original C/R/O pins. No HELD/live/uncertain holder may be forgotten; keep original generations and stop-only recovery alive through the original deadline. Observe stop submission, owner26 acknowledgement separately from exit, pidfd exits, wait/reap, cgroup membership/events and protected journal/capture. Classify application cleanup Confirmed only with required independent readbacks; otherwise Unknown/Failed and retain evidence and resources for diagnosis. A missing C or shell exit0 is insufficient.

After application verdict, export evidence with hashes to an owner-selected host directory; verify export and retained source/candidate identities before any distro removal. Do not use `remove-generation` to claim GC: current implementation always refuses independent cleanup/ownership uncertainty, including every current holder state. No automatic deletion of active/HELD/live/uncertain generations. An uncertain environment is quarantined and retained unless a later explicit owner destruction decision accepts the loss of live obligations; that destruction cannot count as Gagamba cleanup success. Only an independently empty/stopped test unit and exact named disposable distro/storage become eligible for separately authorized teardown. Never use `wsl --shutdown` for this task or delete historical worktrees.
