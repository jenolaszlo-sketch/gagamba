# AR-7 P03 design — Linux transports and host IPC (design only, not executed)

Date: 2026-10-10. Status: **DESIGN ONLY. No harness written, no probe executed,
no fixture created.** Execution requires separate review of this document.

## Design question (from the P03 record)

Can the surviving Linux candidate prevent all unprepared IP networking and
host-service IPC while preserving explicitly prepared data channels?

Scope: **Linux rootless candidate only** — the exact P02 composition (pinned
non-setuid Bubblewrap 0.11.1, user/mount/PID/net/IPC/UTS namespaces, nested
userns disabled and asserted, cap-drop ALL, `no_new_privs`, read-only static
`/target` + `/input`, private `/proc` + `/dev`, 8 MiB tmpfs scratch, empty
`/sys` + `/run`, no host cgroupfs, prepared anonymous stdio only, same cBPF
filter bytes, same cgroup/memory/pids leaves). Windows is not revisited: P01
blocked LPAC+Job and P01B ended without a candidate. No P04/P07 work. No
production Gagamba changes. No architecture repair if the candidate fails:
any established unprepared channel is a `BLOCKED BY THIS PROBE` outcome.

## 1. Proposed harness architecture

Three roles, same trust split as P02:

- **Root observer/provisioner** (new `p03.py` observer mode, UID 0): provisions
  the disposable fixture, compiles the static worker, verifies pins, starts the
  manager dropped to UID 65534, samples cgroup domains and target status from
  outside the fixture domain, enforces the 30-second watchdog, kills via the
  outer `cgroup.kill`, reaps, verifies cleanup, writes the raw record. Root
  never enters target authority and never handles the nonce except as an
  opaque directory name.
- **Manager + endpoint oracles** (`p03.py` manager mode, UID/GID 65534, host
  network namespace, no namespaces/seccomp of its own): owns all synthetic
  listeners, runs the ordinary positive worker first, checks the positive gate,
  releases the restricted candidate only if the gate holds, drains every
  listener in both phases, and reports.
- **Worker** (new static C `p03.c`, two modes): `positive` runs in the host
  network namespace with no namespaces/seccomp and must complete every
  endpoint exchange; `candidate` runs under the exact P02 bwrap invocation and
  attempts the restricted matrix while performing useful work (read `/input`,
  write bounded scratch, nonce echo over prepared stdio, exit 0).

All socket, DNS, HTTP, agent-protocol, netlink, and io_uring operations use
direct OS APIs (raw `syscall()` numbers, hand-built messages) in the static
worker. No high-level networking libraries, no NSS/getaddrinfo (the candidate
has no `/etc` or resolver configuration by construction), no real metadata
services, SSH agents, daemons, credentials, or production endpoints.

## 3. Positive-control matrix (ordinary worker, host netns, no ns/seccomp)

For every endpoint 1–3 and 5–11, the ordinary worker must complete **both** the
direct path (`socket()` → connect → send exact nonce → receive the canned
reply) **and** the io_uring path (same SQE chain the candidate will use:
`IORING_OP_SOCKET` → `CONNECT` → `SEND` → `RECV`, nonce exchanged, canned
reply received), and the oracle must log the matching entries (Section 5).
An io_uring path that fails in the positive control (e.g. `ENOSYS` for an
unsupported operation) marks that variant `INCONCLUSIVE` — it is never
evidence that the candidate blocked it. Endpoint 4 must show host `lo` UP with
addresses. Endpoint 12 must complete the stdin/stdout nonce echo with no extra
FDs. These run **before** any candidate release under the gate rule: all
positive exchanges succeed AND all oracle entries match AND manager limits are
unchanged, otherwise the run is `INCONCLUSIVE` and no target is released —
exactly the P02 `positive_gate` discipline. An unreachable positive-control
endpoint is never counted as isolation; the affected legs are marked
`INCONCLUSIVE` (Section 9), never passed.

## 4. Restricted-attempt matrix (candidate, exact P02 composition)

Useful-work gate (must hold or the run is `INCONCLUSIVE`): `/input` read of 32
nonce bytes, bounded scratch write, nonce echo over prepared stdio, finite
child, exit 0.

Per unprepared endpoint, two attempt paths, each fully logged with return
code and errno:

- **(a) Direct-syscall path**: `socket()` → connect → request. Expected denial
  at `socket()` with EPERM under the frozen filter. Any further progress is
  recorded exactly as observed, never reinterpreted.
- **(b) io_uring path** (deferred from P02 to this probe): `io_uring_setup` +
  `IORING_OP_SOCKET` → `CONNECT` → `SEND`, one SQE chain per IP/Unix endpoint.
  The P02 filter does not cover the io_uring syscalls, so this path tests
  whether the network namespace (no routes, loopback down), the capability
  ceiling (zero), and the userns-disablement hold without filter help.
  Acceptance is: no oracle request logged AND no established channel AND no
  returned FD usable for data. Exact errnos are recorded as-is:
  `ENETUNREACH`/`EACCES` describe namespace/capability barriers, not filter
  denials — the evidence must say which barrier held.

Additional authority attempts: bring `lo` UP via netlink (`socket()` EPERM;
then io_uring `AF_NETLINK` socket → `RTM_NEWLINK`, expected EPERM for want of
`CAP_NET_ADMIN`); raw sockets, safely bounded to loopback: `SOCK_RAW`
creation is expected EPERM for **both** ordinary and candidate callers (neither
holds `CAP_NET_RAW`), so that symmetry is documented, not counted as a
candidate-specific denial — the counted raw leg is an unprivileged ICMP echo
(`SOCK_DGRAM`, `IPPROTO_ICMP`) to `127.0.0.1`, which the positive control must
complete, plus the io_uring `SOCK_RAW` socket → send attempt, expected EPERM
at send for the candidate for want of `CAP_NET_RAW`; create a new userns+netns
pair (`unshare`/`clone NEW*`, expected EPERM); mount `cgroup2`/`proc`
(expected EPERM); `setns` on fixture and init references (expected EPERM;
actual kernel authorization comparison stays `INCONCLUSIVE` per the P02
precedent). `/sys/class/net` access is expected ENOENT (visibility exclusion,
not an ACL denial — same discipline as P02).

## 5. External-oracle design

- **Endpoint oracles** (manager, host netns): one bounded listener per
  endpoint, each accepting only during the run window, each logging
  `{endpoint, request-bytes, peer PID/UID/GID via SO_PEERCRED where the
  transport supports it, monotonic timestamp}`. TCP/Unix listeners use
  `SO_PEERCRED`; UDP/DNS legs log source address + payload. The candidate
  phase must produce **zero** log entries; any entry with the run nonce is a
  `BLOCKED BY THIS PROBE` finding with the exact bytes preserved.
- **Domain oracle** (root observer, outside the fixture domain): periodic
  sampling of fixture PIDs only — cgroup membership, `/proc` status
  (UID 65534, `NoNewPrivs:1`, `Seccomp:2/filters:1`, zero caps for the
  target), command lines — plus the P02 kill/reap/populated-0 protocol.
- **Independence**: the oracle never trusts worker return values; denials
  count only with a passed positive gate plus oracle silence plus unchanged
  manager limits.

## 6. Provisioning requirements (root; outside target authority)

Root does the following, and nothing else, before any target exists:

1. Create the fixture workspace (`/tmp/gagamba-ar7-P03-<nonce>`, `0700`).
2. Compile the static worker (`gcc -static -O2 -Wall -Wextra`); abort before
   release on any compile failure.
3. Verify pins: Bubblewrap hash `523da3e7…` and mode `0755` non-setuid/non-setgid;
   kernel ≥ 5.19 for `IORING_OP_SOCKET` (else io_uring legs are pre-marked
   `INCONCLUSIVE`); `user.max_user_namespaces` present; cgroup v2 mounted
   `rw` with `nsdelegate`; `memory`+`pids` controllers delegatable.
4. Build the cgroup tree exactly as P02 (outer 256 MiB/swap 0/64 tasks;
   delegated 128 MiB/48 tasks; `manager`/`target`/`sibling` leaves chowned to
   65534). All migration destinations stay inside the outer cgroup.
5. Provision the metadata address: `ip addr add 169.254.169.254/32 dev lo` in
   the **host** namespace (root-owned, disposable, removed at cleanup). The
   responder uses an ephemeral high port, not `:80`: an unprivileged manager
   cannot bind low ports, and destination-address reachability — not the port
   number — is the tested property. If assignment fails, leg 7 is
   `INCONCLUSIVE`, not passed. Probe `[::1]` bindability the same way for
   leg 2.
6. No sysctl changes, no new users/daemons/setuid, no service or firewall
   changes, no credential material anywhere. Safety bounds identical to P02
   (`RLIMIT_FSIZE` 1 MiB, `RLIMIT_NOFILE` 64, `RLIMIT_CORE` 0, `RLIMIT_CPU`
   12 s, native `alarm(12)`, observer watchdog 30 s, finite children, bounded
   32 KiB outputs). These bounds are fixture safety, not P04 qualification.

Privileged setup stays outside target authority because every provisioned
object is created by the root observer before the UID drop, addressed only by
observer-generated paths, and owned outside the delegated leaves the target
can name; the target's view (empty `/sys`, no host cgroupfs, private `/proc`)
cannot address the provisioning channel.

## 7. Cleanup procedure (identities fixed before release)

Cleanup identities: outer cgroup path, delegated tree with the known leaf set
(`manager`, `target`, `sibling`, `new-positive`, `new-candidate`), workspace
files (`worker`, `input`), the metadata loopback address, all listener
sockets. Order: `cgroup.kill` on outer → reap manager → require `populated 0`
→ rmdir known leaves → rmdir delegated → rmdir outer → remove metadata
address → unlink workspace files → rmdir workspace. Never recursively delete
target-provided paths. Unknown cgroup descendants are preserved, the run is
marked cleanup-uncertain, and **all AR-7 work on the host stops**. An
independent post-run check verifies workspace/cgroup/endpoint/nonce absence
for the nonce, as in P02.

## 9. Ambiguity and failure conditions

- Any positive-control endpoint unreachable → affected legs `INCONCLUSIVE`,
  no release if the gate fails; never a pass.
- `ENETUNREACH` on an io_uring path = namespace barrier held, recorded as
  such; it is not a filter denial and not a general networking proof.
- `io_uring` `ENOSYS` (old kernel/headers) → io_uring variants
  `INCONCLUSIVE`, other legs unaffected.
- IPv6 bind unavailable → leg 2 `INCONCLUSIVE`.
- Metadata address assignment unavailable → leg 7 `INCONCLUSIVE`.
- Actual `setns` authorization comparison stays `INCONCLUSIVE` (P02 precedent:
  the positive control also fails there).
- `ENOENT` on `/sys` paths = visibility exclusion, never an ACL claim.
- Seccomp filter hash is self-reported in-band; corroboration is behavioral
  (EPERM at the gated calls) plus external `Seccomp:2/filters:1` status.
- Candidate useful-work failure → whole run `INCONCLUSIVE`.
- Any run-nonce request in any oracle log during the candidate phase, any
  established unprepared channel, or any candidate-enabled networking
  (lo up, new netns, changed limits) → `BLOCKED BY THIS PROBE`; no repair,
  Linux track ends, record and stop.
- Watchdog fire or cleanup uncertainty → `INCONCLUSIVE` plus the shared-host
  stop rule (Section 7).

## 10. Exact proposed execution sequence

0. Review this design; commit the harness (`p03.c`, `p03.py`) only after
   review. No source change after step 5 without a new commit.
1. Root observer generates the nonce, workspace, and cgroup paths.
2. Compile the static worker; abort on failure (no release).
3. Verify all pins and preconditions (Section 6, steps 3–5); pre-mark
   unavailable legs `INCONCLUSIVE` in the record.
4. Drop to UID 65534 and start the manager; manager starts all listeners and
   runs the ordinary positive worker.
5. Check the positive gate (Section 3). Gate failure → `INCONCLUSIVE`, skip
   to step 9. No candidate release.
6. Gate held → release the restricted candidate under the exact P02 bwrap
   invocation with the run nonce; root observer samples domains.
7. Candidate completes (or native alarm fires); manager drains all listeners.
8. Assert: zero oracle entries for the nonce, limits unchanged, target domain
   empty, useful-work outputs exact.
9. Root kills via outer `cgroup.kill`, reaps, requires `populated 0`, removes
   only the Section-7 identities in order; aborts to the stop rule on any
   unknown residue.
10. Independent post-run absence check for the nonce (paths, cgroups,
    endpoint names).
11. Read-only reviewer challenge of recipe, raw record, and narrow conclusion
    before any disposition is recorded.
12. Write the Section-8 evidence files, commit, update aggregate/queue/handoff
    docs-only. Then stop: no P04/P07, no repair, no production changes.

**Explicit non-execution note:** steps 1–12 are not authorized by this design.
No code was written and no fixture was created in this turn.
