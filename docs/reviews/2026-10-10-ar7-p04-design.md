# AR-7 P04 design — Linux resource and writable-storage bounds (design only, not executed)

Date: 2026-10-10. Status: **DESIGN ONLY. No harness written, no probe executed,
no fixture created.** Execution requires separate review of this document.

## Design question

Can this candidate bound resource consumption and writable state honestly
enough for `restricted-offline-closure-v1` while still running useful native
and self-contained .NET workloads?

Scope: **Linux rootless candidate only**, frozen to the exact P02/P03
composition (pinned non-setuid Bubblewrap 0.11.1, same namespaces/cap-drop/
`no_new_privs`/cBPF bytes/cgroup topology). The workload closure content
varies by case (native static binary; self-contained publish folder ro-bound
at `/app` alongside ro `/input`) — that is the workload under test, not a
mechanism change. No new sandbox restrictions merely to make resource tests
pass: if a bounded case fails, the outcome is `BLOCKED BY THIS PROBE`, not a
tuning task. No production Gagamba changes. No P07 work.

The illustrative 128 MiB budget is **not sacred**. If self-contained .NET
cannot start within it, the probe measures the actual minimum and returns it
as architecture input. The profile is never silently raised during the probe.

## 1. Fixture architecture

Three roles, same trust split as P02/P03:

- **Root observer/provisioner** (new `p04.py` observer mode, UID 0): workspace,
  static compile, .NET staging verification (not the publish itself — see §4),
  helper pin, cgroup tree (outer 256 MiB/swap 0/64 tasks; delegated
  128 MiB/48 tasks; `manager`/`target`/`sibling` leaves), sampling of
  `memory.peak`, `memory.events`, `pids.events`, and target status from
  outside the fixture domain, 30-second watchdog, kill/reap/populated-0
  protocol, evidence record. Root never enters target authority.
- **Manager** (`p04.py` manager mode, UID/GID 65534, host netns): runs each
  workload case first as an unbounded-but-observed positive control (same
  binary, host cgroup, no candidate limits), checks case gates, then releases
  the restricted candidate case-by-case under the exact P02 bwrap invocation
  (plus the ro `/app` workload bind for .NET cases only). No listeners are
  needed; the oracles are cgroup counters and byte counts (Section 8).
- **Workers**: native static `p04.c` with small bounded modes (Section 3);
  self-contained .NET app (Section 4) printing bounded diagnostics to
  stdout. All worker output is bounded (32 KiB caps, as before); every case
  has a native `alarm(12)` plus the observer watchdog.

Candidate environment additions over P02, all workload preparation and
configuration (not mechanism, not enforcement): `HOME=/tmp`,
`DOTNET_GCServer=0` (deterministic workstation GC; recorded, not tuned to
pass), invariant globalization (no ICU dependency), and the ro `/app`
workload bind for .NET cases. None of these adds sandbox enforcement, and
`HOME=/tmp` in particular must not be used as evidence that other writable
paths are unavailable: writable-state accounting comes only from the
candidate's observed mount/filesystem view (`/proc/self/mountinfo` cross-cut,
Section 7) and direct bounded tests. No `DOTNET_GCHeapHardLimit*` or other
heap-sizing knobs: .NET must face the 128 MiB ceiling naturally, because the
candidate hides the limit value (empty `/sys`, no host cgroupfs) while
exposing the v2 path — that mismatch is itself a measured behavior, not a
setup bug to fix mid-probe.

## 2. Resource-budget matrix (requested limits → where enforcement is observed)

| Budget | Requested (mechanism) | Observed (oracle) |
| --- | --- | --- |
| Delegated memory 128 MiB (`memory.max`) | `delegated/memory.max` | `memory.peak`, `memory.events:oom_kill/max`, exit signal |
| Swap behavior (`memory.swap.max`, availability/use) | `outer/memory.swap.max=0`; swap availability read from host view only | `memory.swap.current==0` post-load; any swap use is a finding, not an assumption; outer never OOMs |
| Outer memory 256 MiB (host safety, not profile) | `outer/memory.max` | outer `memory.peak` stays far below ceiling on every case; outer never OOMs |
| Sibling 64 MiB/16 tasks (control fixture) | leaf limits | unchanged after every run |
| Task/thread accounting (`pids.max` counts Linux tasks, not processes) | `delegated/pids.max=48` | `pids.events:max`, `pthread_create` EAGAIN point, worker-reported created threads cross-checked against the counter; `/proc/self/status Threads:` reported as tasks, never relabeled as processes |
| Tmpfs byte ceiling | `--size 8388608` on `/tmp` | exact bytes written to `ENOSPC` |
| Tmpfs inode/metadata ceiling | same tmpfs instance (no separate limit configured) | exact file count to `ENOSPC`, separately from the byte count |
| Requested allocation vs pages actually touched | workload requests N MiB | worker touches + checksums back every page; untouched mappings are non-evidence (overcommit); peak attributed only to verified-touched pages |
| Process-visible failure vs independent counters | worker-observed errno/exit/signal | the same event in cgroup counters (`oom_kill`, `max`, `pids.events`); a visible failure without the matching counter (or vice versa) is an ambiguity finding, not a pass |
| FD table 64 | `RLIMIT_NOFILE` (inherited through exec) | opens to EMFILE, exact count |
| Core dumps off | `RLIMIT_CORE 0` | no core file in any writable location after forced crash |
| CPU 12 s | `RLIMIT_CPU` + `alarm(12)` | no run exceeds; watchdog never fires on a valid run |
| Output 32 KiB streams | manager-side capture caps | bytes emitted vs retained, no hang, exit code preserved |
| `/dev/shm` | inventoried (size/visibility measured, not assumed) | bounded write + host-invisibility check |

There is deliberately **no** cgroup fd controller and no I/O controller in
this composition; FDs are bounded by rlimit only, and that limit is stated,
not implied.

## 3. Native workload cases (`p04.c`, static, direct syscalls)

- `mem N`: `mmap` N MiB anonymous, touch every page (read+write one byte),
  verify by checksumming back, hold 1 s, report peak RSS from
  `/proc/self/status`, exit 0. Touching is mandatory: pure `malloc` without
  touch proves nothing under overcommit, and untouching allocators are
  recorded as non-evidence.
- `threads N`: spawn N joinable pthreads each touching 1 MiB and sleeping
  1 s; report created count, `EAGAIN` point, and `/proc/self/status`
  `Threads:` value. Task count (what `pids.max` enforces) is reported, never
  relabeled as process count.
- `scratch-fill`: write 1 MiB blocks to `/tmp/fill-N` until `ENOSPC`; report
  total bytes + file count; then `unlink` and report reuse.
- `inode-fill`: create empty files until `ENOSPC`; report count (metadata
  ceiling); remove them.
- `fd-consume`: open `/dev/null` until `EMFILE`; report exact count.
- `shm-probe`: `shmget` 16 MiB + attach + touch + detach + `IPCRMID`;
  report peak effect or errno. (Private IPC namespace; memory must still
  land inside the 128 MiB accounting — verified via `memory.peak`.)
- `shm-path`: 1 MiB file in `/dev/shm`, report; host-invisibility checked
  by the oracle (Section 8).
- `oomscore`: attempt to lower `/proc/self/oom_score_adj` (expected EPERM
  without `CAP_SYS_RESOURCE`); raising it must succeed (more-killable is
  unprivileged). OOM-evasion denial is the counted property.
- `mountinfo`: dump `/proc/self/mountinfo` (closure argument for Section 7).
- `big-output`: emit 1 MiB of patterned stdout + 64 KiB stderr; exit 17
  (exit code must survive truncation).
- `crash-abort`: `abort()` after writing a marker to `/tmp`; oracle checks
  SIGABRT delivery, empty domain, and absence of core files.
- `null-writes`: bounded writes to `/dev/null`, `/dev/zero` read cap, ro
  `/target` write attempt (expected EROFS: visible-denied, contrasted with
  ENOENT invisibility in the inventory).

## 4. Self-contained .NET workload cases

- Staging (provisioning-time host activity, not target): publish on the
  Windows host with `dotnet publish -c Release -r linux-x64 --self-contained
  -o <ignored staging> /p:InvariantGlobalization=true` (regular folder
  publish — **not** single-file, whose bundle extraction would need tens of
  MiB beyond the fixed 8 MiB tmpfs; that constraint is documented, not
  worked around). Stage under ignored `artifacts/ar7/P04/dotnet/`. If
  publish fails (e.g. no network for the runtime pack), all .NET legs are
  `INCONCLUSIVE`, never skipped silently.
- Minimal app (`Program.cs`, committed source): prints granted-env subset,
  reads ro `/input`, writes bounded `/tmp` scratch, optionally allocates a
  configured MiB array (touched + checksummed), optionally spawns configured
  threads, prints `GC.GetTotalMemory`, `Process.Threads.Count`, and
  `Environment.WorkingSet`, exits 0. No network/registry/config-file use.
- Cases: `hello` (no alloc — measures the startup minimum), `hello+64MiB`
  (steady-state), `hello+192MiB` (bounded above-budget: expect OOM-kill, per
  Section 6). Repeat each 3×; report peak range (GC nondeterminism is
  expected and bounded by repetition, not hidden).
- If `hello` alone exceeds 128 MiB: the finding is "self-contained .NET
  startup minimum is X on this host," returned as architecture input. The
  profile stays at 128 MiB for the rest of the probe.

## 5. Below-budget success cases (must all hold or the run is INCONCLUSIVE)

Native `mem 64` completes with peak ≈ baseline+64 MiB and no OOM event;
`threads 8/40` complete with exact created counts; scratch/inode fills stop
exactly at `ENOSPC` with recorded byte/file counts; fd-consume stops at
`EMFILE` with count ≈ 61; `.NET hello` and `hello+64MiB` exit 0 with peaks
under 128 MiB (or the measured-minimum finding above); `big-output` exits 17
with retained-prefix intact; prepared stdio echo works in every case.

## 6. Bounded above-budget failure cases (each sized to trip delegated limits while staying far under the 256 MiB outer ceiling; strictly sequential)

- `mem 192` touched: expect OOM-kill (`memory.events:oom_kill` increments,
  exit by SIGKILL, peak ≈ 128 MiB). The 64 MiB headroom to the outer ceiling
  is the host-safety margin — never narrowed.
- `threads 60`: expect `EAGAIN` past the task budget with exact created
  count + `pids.events:max` increment; no OOM, no hang.
- Scratch/inode overflow past ENOSPC: further writes fail cleanly, earlier
  bytes intact, exit code truthful (no silent truncation claims).
- FD past EMFILE, `/dev/shm` past its measured size, stdout past 32 KiB
  (retained prefix + exit code intact).
- A `mem 240` case is explicitly **excluded**: too close to the outer
  ceiling to keep the safety margin honest.

## 7. Writable-state inventory (exhaustive by construction, not by sampling)

The worker dumps `/proc/self/mountinfo`; the oracle cross-checks it against
the expected mount set (`/`, `/proc`, `/dev`, 8 MiB `/tmp`, empty `/sys`
+ `/run`, ro `/target` + `/input` + `/app`). Any extra writable mount is a
finding. Each enumerated location is classified:

- **Bounded**: `/tmp` (8 MiB + inode ceiling, measured), `/dev/shm`
  (measured size; host-invisibility verified), pipes (reader-bounded).
- **Visible-denied**: ro closure (`EROFS`), `oom_score_adj` lowering
  (EPERM), `/proc/sys/*` (read-only view).
- **Invisible**: `/sys`, host cgroupfs, host paths (ENOENT — visibility
  exclusion, never presented as denial).
- **Sinks**: `/dev/null`/`zero`/`full` (bounded by semantics; `/dev/full`
  ENOSPC behavior recorded as the honest-write-failure control).
- **Pseudo-writable**: `/proc/self/oom_score_adj` (raising allowed),
  SysV SHM (private ns, memcg-accounted — verified via peak, not assumed).

If any writable authority cannot be completely accounted for, the evidence
records the uncertainty explicitly rather than assuming closure.

## 8. Independent measurement/oracle design

Root observer (outside the fixture domain) records per case, post-return
(deterministic, not live-sampled): `memory.peak`, `memory.events`
(`oom_kill`, `max`), `pids.events`, `memory.swap.current`,
exit code/signal, stdout bytes emitted (worker self-report) vs retained
(manager-measured), input-file hash unchanged, no new workspace files,
host `/dev/shm` free of candidate files (privateness proof), target domain
empty. No trust in worker self-reports for enforcement facts; worker reports
are cross-checked against counters (e.g. claimed thread count vs
`pids.events`, claimed bytes vs `ENOSPC` point + peak delta).

## 9. Host-safety ceilings

Outer 256 MiB + swap 0 + 64 tasks bounds the entire fixture tree; every
above-budget case is sized ≤192 MiB touched with the delegated 128 MiB
tripping first; one stress case at a time, sequential, with kill/reap/
`populated 0` between cases; CPU 12 s + `alarm(12)` + 30 s observer
watchdog; tmpfs sizes fixed at spawn (nothing resizable by the target);
no loop devices, no swapfiles, no sysctl writes, no host mounts. Watchdog
fire or cleanup uncertainty stops all AR-7 work on the host.

## 10. Cleanup design (identities fixed before release)

Per case: kill target leaf via outer `cgroup.kill`, reap, require
`populated 0`; counters read before teardown; remove only known identities
(workspace `worker`/`input`/sockets, `/app` staging bind source untouched —
it is read-only shared staging, never per-case residue; tmpfs and namespaces
vanish with the last target). Unknown cgroup descendants, unexpected
workspace files, host `/dev/shm` residue, or uncleared counters abort to
the shared-host stop rule. Independent post-run absence check per nonce,
as in P02/P03.

## 11. Ambiguity and stop rules

- Untouched allocations are non-evidence (overcommit); every memory case
  touches + verifies by readback.
- Anonymous vs page-cache: cases use anon `mmap`/managed arrays only;
  file-backed mappings are excluded from byte claims.
- GC nondeterminism: 3× repetition with range reported; `DOTNET_GCServer=0`
  fixed and recorded.
- THP granularity noted on RSS/peak readings; `memory.peak` (not live RSS
  sampling) is the enforcement measure.
- OOM victim is unambiguous (single workload per target leaf).
- `setns`-style authorization comparisons stay `INCONCLUSIVE` where the
  positive also fails (P02/P03 precedent).
- Any established unprepared channel, any limit unchanged-after-violation,
  any unaccounted writable location → finding, not tuning: `BLOCKED` or
  explicit uncertainty; no profile edits, no knob adjustments, no reruns
  that shrink the workload to fit.
- Watchdog/cleanup uncertainty → `INCONCLUSIVE` + stop-all-work rule.

## 13. Exact proposed execution sequence

0. Review this design; publish the .NET staging and commit the harness
   (`p04.c`, `p04.py`, `dotnet/Program.cs`) only after review. No source
   change after step 5 without a new commit.
1. Root observer generates nonce/paths; verifies pins (helper hash/mode,
   userns, cgroup delegation, swap control).
2. Compile native worker (fail → setup error, no release); verify .NET
   staging present and input hashes recorded (absent → .NET legs
   pre-marked `INCONCLUSIVE`, native legs proceed).
3. Run positive controls per case in the host context (unbounded, observed);
   record natural peaks/counts as the comparison baseline.
4. Release restricted candidate case-by-case in budget order (startup →
   steady-state → bounded above-budget), one stress at a time, with
   kill/reap/empty-domain between cases.
5. Assert per case: gate markers, oracle counters, byte accounting,
   exit/signal truthfulness, domain emptiness.
6. Kill via outer `cgroup.kill`, reap, require `populated 0`, remove only
   Section-10 identities; abort to the stop rule on residue.
7. Independent post-run absence check for the nonce.
8. Read-only reviewer challenge before any disposition is recorded.
9. Write Section-12 evidence, commit, update aggregate/queue/handoff
   docs-only. Then stop: no P07, no repair, no production changes.
