# AR-7 P07 design — Linux crash, ownership, and release semantics (design only, not executed)

Date: 2026-10-10. Status: **DESIGN ONLY. No harness written, no probe executed,
no fixture created.** Execution requires separate review of this document.

## Design question

Can the topology guarantee that failures during setup, release, execution,
cancellation, and teardown never produce a target that is both released and
no longer lifecycle-owned — while preserving truthful distinction between
target-root completion, wrapper/helper completion, and loss of observation?

Scope: **Linux rootless candidate only**, frozen to the exact surviving
P02/P03/P04 execution topology (pinned non-setuid Bubblewrap 0.11.1, same
namespaces/cap-drop/`no_new_privs`/cBPF bytes, same cgroup topology with
explicit target 128 MiB/48 tasks, same workload-closure pattern). No
candidate repair, no new confinement mechanism, no guardian/service process:
no guardian exists in this topology, and if the acceptance criteria require
one, the verdict is `HELPER TOPOLOGY UNRESOLVED` — reported, never
implemented here. No production Gagamba changes.

## 1. Process/topology diagram (per run, one fixture nonce)

```text
observer (root, host cgroup, outside fixture domain)
 └─ manager (UID 65534, delegated/manager leaf)
     ├─ (listeners: none in P07; oracles are counters, timelines, exit states)
     └─ bwrap-outer (UID 65534, target leaf; setup phase: userns+mounts+filter)
         └─ bwrap-ns (namespace init, host-PID N, ns-PID 1, target leaf)
             └─ /target root (ns-PID 2, target leaf)
                 └─ finite children (ns-PID 3+, target leaf; bounded count)
```

Cgroups: `outer` (256 MiB/swap 0/64 tasks) → `delegated` (pass-through
256/64) → `manager` / `target` (explicit 128 MiB/48) / `sibling` (64 MiB/16)
/ `positive` leaves. Stop path: `outer/cgroup.kill` (SIGKILL, unblockable),
reap, require `populated 0`. Timeouts: native `alarm(12)`, per-case launch
bound 20 s, observer watchdog 480 s for the suite. All fixture paths derive
from the run nonce; runs are strictly single-flight.

## 2. Ownership model

Ownership is kernel-enforced, in this precedence order — no userspace
guardian is trusted for it:

1. **cgroup kill/reap**: any process in the fixture subtree is stoppable via
   the outer `cgroup.kill` regardless of parentage, doubled-forks, sessions,
   or ignored signals; emptiness is proven by `populated 0`, not by PID
   absence.
2. **PID-namespace init death cascade**: if the ns init (bwrap-ns child)
   dies, the kernel SIGKILLs every remaining member of that PID namespace.
   `--die-with-parent` additionally couples the bwrap chain upward.
3. **Observer enforcement**: the root observer (outside the fixture domain)
   owns kill/reap/teardown and never delegates stop authority to the
   manager, the helper, or the target.
4. **Manager coordination only**: the manager releases candidates and
   records observations; it owns no cleanup (all removal paths are
   observer-side, as in P02–P04) and its death is survivable by design.

What is deliberately NOT claimed: PID-based tracking, cooperative shutdown,
or any userspace supervisor standing between the observer and the kernel
mechanisms above.

## 3. Release barrier/state machine

Release commits exactly at the `bwrap` exec into `/target`. Before that
point the states are:

- `UNRELEASED` (setup/provisioning; nothing runnable exists),
- `CANCELLED-BEFORE-RELEASE` (a stop won first; release is refused),
- `RELEASED-OWNED` (target exists AND domain membership is tracked),
- terminal observations (Section 6), never inferred.

Rules: no release after cancellation/stop has won (barrier checked
immediately pre-release, Section 5); a release always lands inside the
tracked domain (creation-time cgroup placement, inherited by every
descendant — cgroup membership cannot be left by `fork`/`setsid`/double-fork
without a mount/namespace authority the candidate does not have); the
linearisation point for races is defined in Section 5.

## 4. Crash matrix (each a bounded case with pre-declared expectations)

| # | Fault (all by root-owned orchestration, never by the target) | Expectation |
| --- | --- | --- |
| C1 | Caller (probe driver) dies before any setup | Nothing created; independent audit finds no nonce residue (vacuous, recorded) |
| C2 | Caller dies mid-provisioning | Partial state reaped via nonce manifest (single-flight, root-only manifest written step-by-step; a later audit completes/removes it; never pattern-deletes) |
| C3 | Manager dies (SIGKILL) before release | No target exists; manager leaf empties; observer reaps + verifies; no release counted |
| C4 | Manager dies immediately after release | Target + helper chain orphaned in target leaf; observer kills via outer `cgroup.kill`, verifies `populated 0`; root status recorded UNKNOWN (never inferred) |
| C5 | bwrap-outer dies mid-setup | Setup aborts; no target; domain verified empty |
| C6 | Namespace init dies (host-PID kill of ns-PID 1) | Kernel cascade kills the namespace; domain verified empty |
| C7 | Root target exits (0/17) while a finite child sleeps on | Root result known (exit code); domain NON-empty afterwards; completion NOT reported until empty; final cleanup still empties |
| C8 | Descendant holds the stdout pipe 5 s past root exit | Manager returns only after pipe closes (launch bound covers); output complete, exit code preserved; no truncation-by-timeout |
| C9 | Deadline fires during setup (`hang-setup` fault + short watchdog, documented alarm-test) | Watchdog path kills + sweeps by manifest; verified empty |
| C10 | Target killed directly (SIGKILL to target root) | Death observed; siblings/children die via domain kill; status truthful per Section 6 |

Deterministic self-kill mechanism (no timing races where avoidable): the
candidate prints a `RELEASED` marker the manager reads from its stdout pipe;
for C4 the manager raises SIGKILL to itself upon reading it — release then
death, ordered by construction. C3 kills before any spawn. The wrapper
(`p07-caller`, new minimal harness surface) spawns the observer-as-child for
C1/C2 with kill scheduling plus post-mortem audit by nonce.

## 5. Cancellation/deadline race matrix

- **Deterministic cancel**: cancel-flag file present in the workspace before
  spawn → manager must refuse every release (`CANCELLED-BEFORE-RELEASE`,
  zero spawns, verified by empty target domain + absent bwrap samples).
- **Racy cancel** (5 bounded rounds): root creates the flag at random 0–500 ms
  after spawn; manager checks immediately pre-release and records its own
  monotonic timestamp vs the flag mtime. Linearisation rule: flag mtime
  earlier than the recorded pre-release instant ⇒ release must have been
  refused; release committed first ⇒ correct ONLY with ownership held and
  full cleanup afterwards (both recorded). A lost race with intact ownership
  is not a failure; a release after a won cancellation is `BLOCKED`.
- **Deadline during setup**: C9 above (short watchdog, alarm-test).
- **No release after stop won**: the conjunction of the three; any
  counterexample ends the Linux track (`BLOCKED`), no repair.

## 6. Root-vs-wrapper result model (separate fields, never merged)

Per case: `root_result` {exit code | signal | **unknown**},
`wrapper_result` (bwrap exit: 0 | 128+signo convention per P04 | launch
failure), `domain` {empty@t | non-empty@t with timestamps},
`cleanup` {confirmed | failed | unknown}. Rules: wrapper-ok ⇏ root-ok;
root-ok ⇏ descendants-gone; empty-domain + unknown-root ⇒ root stays
**unknown**; a missing PID is never used to kill anything later (Section 8).

## 7. Descendant-survival cases (bounded; each must end domain-empty)

- Natural exit with sleeping child (C7), pipe-holding child (C8).
- Double-fork daemonizer (fork + `setsid` + parent exits): reparented child
  inherits the target leaf → still killed via `cgroup.kill`; verify leaf
  membership pre-kill and emptiness after.
- Bounded rapid-forker (20 children max, `pids.max` caps at 48): kill
  mid-spawn, assert empty after; no fork-bomb risk by construction.
- Re-exec of `/target` inside the sandbox: seccomp + NNP inherit across
  `execve` (confinement preserved); marker distinguishes generations.
- `PR_SET_PDEATHSIG` games, `cgroup.procs` writes (expect `ENOENT`, P02
  precedent), `setns` to host/init namespaces (expect `EPERM`), `mount`
  attempts (expect `EPERM`): each attempted, each recorded; any escape or
  survival past domain kill ⇒ `HELPER TOPOLOGY UNRESOLVED`.

## 8. Stale-identity/PID-reuse strategy

- All stop decisions go through `cgroup.kill` + `populated` polling: **no
  PID is ever addressed for killing**.
- Every PID-based observation (sampling, parent-chain discovery for the
  ns-init kill in C6) is validated per sample: `/proc/PID/cgroup` must
  contain the fixture path AND `/proc/PID/stat` starttime (field 22) must
  match the observation window. Samples failing validation are discarded,
  never acted on.
- An observed-absent PID is never reused for later action; each action
  re-validates. Post-teardown, no PID value is retained except inside the
  sealed evidence record (for audit, not for action).

## 9. Independent watchdog/oracle design

- Root observer (outside the fixture domain): provisioning, watchdog
  (communicate timeout), kill/reap/empty-domain protocol, evidence record —
  identical authority split to P02–P04.
- Continuous domain-population timeline: the existing sampler thread records
  per-leaf `populated` counts every 50 ms with monotonic timestamps (not
  just post-hoc state) → "empty at T" with time resolution; stragglers are
  visible as timeline tails, never averaged away.
- Manager-side checks (exit codes, markers, counter deltas) corroborate but
  never override the oracle: on any disagreement, the oracle's domain
  observation governs and the case is flagged for review.

## 10. Cleanup states and verification

- **Confirmed**: every Section-10 identity removed (cgroup leaves bottom-up
  after `populated 0`; workspace files by exact name list; host `/dev/shm`
  sweep) plus independent post-run absence check per nonce.
- **Failed**: residue listed with identities; all further AR-7 work on the
  host stops until a reviewed cleanup lands the residue.
- **Unknown**: the observer died mid-teardown (C2/C9 paths) — recorded
  `Unknown`, never inferred clean; a later audit run resolves it via the
  nonce manifest to Confirmed or Failed.
- Cleanup identities are fixed before release (outer path, delegated tree
  with the known leaf set, workspace file list, manifest path); unknown
  descendants are preserved + abort, never recursively deleted.

## 11. Host-safety bounds

Outer 256 MiB/swap 0/64 tasks bounds everything (unchanged); one stress
case at a time, strictly sequential; CPU 12 s + `alarm(12)` + per-case
20 s launch bound + suite watchdog; crash cases add no new resources
(kills only); racy-cancel rounds capped at 5; rapid-forker capped well
under `pids.max`; no loop devices/swapfiles/sysctls/host mounts. Any
watchdog fire or cleanup uncertainty stops all AR-7 work on the host.

## 12. Failure/stop rules

- Any released-but-unowned target, any release after a won stop, any
  surviving descendant past teardown, any target-preserved control
  authority defeating owner death, any meaningless root status, any
  dishonest cleanup state, any stale-identity kill ⇒ record exactly that;
  `BLOCKED BY THIS PROBE` where the topology fails, `HELPER TOPOLOGY
  UNRESOLVED` where a guardian/service/redesign would be needed to proceed.
- No repair, no new mechanism, no production changes, no P05/P06/P08/P09.
- `INCONCLUSIVE` (never a pass) for: failed positive controls, watchdog
  firings without a verdict, cleanup-unknown, or harness faults — each
  skips only its case unless shared-host safety is implicated.

## 14. Exact proposed execution sequence

0. Review this design; commit the harness (`p07.c` with crash/barrier modes,
   `p07.py` observer/manager/wrapper, identity-establishment startup
   barrier) only after review. No source change after step 5 without a new
   commit.
1. Root observer generates nonce/paths/manifest slot; verifies pins
   (helper hash/mode, userns, cgroup delegation, swap control).
2. Compile native worker (fail → setup error, no release); record hashes.
3. Establish identities per case: launch candidate, read its startup ID
   printout, externally validate every PID (cgroup membership + starttime +
   command line) before it proceeds past the barrier.
4. Run the crash matrix C1–C10 in order, one fault at a time; kill/reap/
   verify-empty between cases; record per-case states per Section 6.
5. Run the cancel/deadline matrix (deterministic + 5 racy rounds with
   linearisation timestamps); assert no post-stop release.
6. Run the descendant/interference battery (Section 7); any survival or
   escape ⇒ stop and record `HELPER TOPOLOGY UNRESOLVED` candidacy.
7. Kill via outer `cgroup.kill`, reap, require `populated 0`, remove only
   Section-10 identities; abort to the stop rule on residue.
8. Independent post-run absence check for the nonce (+ manifest cleared).
9. Read-only reviewer challenge before any disposition is recorded.
10. Write Section-13 evidence, commit, update aggregate/queue/handoff
    docs-only. Then stop: no implementation, no repair, no production
    changes.
