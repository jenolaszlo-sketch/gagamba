## Evidence levels and selection rules

**VERIFIED-BYTES** means local actual bytes matched an authenticated expected digest; it does not mean installed or native-qualified. **VERIFIED-METADATA** means authenticated publisher metadata, with signature status stated explicitly; full image/package bytes may be absent. **SOURCE-CONFIRMED** is a code/document requirement. **PROBE-REQUIRED** needs the future environment. **UNRESOLVED** lacks sufficient identity/evidence. Readiness labels in the separate gate table describe whether a fact, implementation or owner decision is still needed; a source requirement is not a pass.

Only exact frozen filenames, package revisions, architectures and hashes may be approved. A mutable suite/current/latest URL is an acquisition location, not an immutable identity. Retain the signed metadata bytes and reject changed content unless rebound and independently reviewed. Package candidates choose signed resolute-updates records when present, otherwise signed resolute base; this selection is **not an apt solver result**. Transitive dependencies, alternatives/conflicts, package scripts and complete payload set must be independently checked before package-install authorization. Preserve reviewable literal transaction inputs, not `apt install latest`.
